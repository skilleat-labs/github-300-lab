# 미션 6-3. 변경 요청 처리

!!! abstract "이 미션에서 할 일"
    - 현업(강사)이 발표한 변경 요청 CR-001을 PO가 이슈로 등록합니다.
    - BA가 Copilot `#codebase`로 영향 분석을 하고, 개발자가 브랜치 `cr-001`에서 Agent로 구현합니다.
    - PR을 병합하면 6-2에서 만든 배포가 현황판을 자동으로 다시 올리는 것을 확인합니다.

**소요 시간** 약 10분  **실습 장소** 팀 리포지토리 `room-booking-team<번호>`  **관련 교안** [6교시 교안](index.md)

## 준비

- 미션 6-2의 현황판 주소 `https://<PO아이디>.github.io/room-booking-team<번호>/`가 열려 있어야 합니다. 지금은 연락처 열이 보입니다.

## STEP 1. 변경 요청 듣기

강사가 현업(총무팀 최수연 대리) 역할로 변경 요청을 발표합니다.

!!! quote "CR-001"
    현황판이 회의실 앞 태블릿과 사외에서도 보입니다. 연락처는 빼고, 예약자는 성과 '○○'로만 보여 주세요. 예: 김○○

킥오프 회의록의 "결정하지 못한 것" 중 **현황판에 연락처를 보여 줄지**가 이렇게 결정된 것입니다. 실제 일에서도 요구는 중간에 바뀝니다. 바뀐 요구를 이슈로 남기고, 영향을 보고, 같은 흐름으로 반영합니다.

확인: CR-001의 두 가지 요구(연락처 빼기, 예약자 `김○○`)를 말할 수 있습니다.

## STEP 2. (PO) 변경 요청 이슈 등록하기

1. github.com 팀 리포지토리 → **Issues** → **Labels** → **New label**로 라벨을 만듭니다.

    ```text
    변경요청
    ```

2. **Issues** → **New issue**를 클릭하고 제목과 본문을 입력합니다.

    ```text
    [변경요청] CR-001
    ```

    ```text
    ## 요청 (총무팀 최수연 대리)
    현황판이 회의실 앞 태블릿과 사외에서도 보입니다. 연락처는 빼고, 예약자는 성과 '○○'로만 보여 주세요. 예: 김○○

    ## 완료 기준
    - 현황판(site/index.html)에 연락처 열이 없다
    - 예약자가 "김○○ (기획팀)"처럼 성과 ○○로만 보인다
    - 예약 데이터(data/reservations.json)와 명령(python -m booking list)은 그대로다

    ## 관련
    킥오프 회의록 "결정하지 못한 것": 현황판에 연락처를 보여 줄지
    ```

3. **Labels**에서 `변경요청`, **Assignees**에서 개발자를 고르고 **Create**를 클릭합니다.
4. 이슈 번호를 팀에 알립니다.

확인: `변경요청` 라벨이 붙은 이슈 `[변경요청] CR-001`이 있습니다.

## STEP 3. (BA) Copilot으로 영향 분석하기

1. VS Code에서 main을 최신으로 맞춥니다.
2. Chat **+**(**New Chat**) → Session Target **Copilot**, Agent **Ask**를 고릅니다.
3. Chat에 붙여 넣기

    ```text
    #codebase 아래 변경 요청을 반영하면 어떤 파일이 바뀌어야 하는지 영향 분석을 해 주세요.

    CR-001: 현황판이 회의실 앞 태블릿과 사외에서도 보입니다. 연락처는 빼고, 예약자는 성과 '○○'로만 보여 주세요. 예: 김○○

    1. 바뀌어야 하는 파일과 이유
    2. 바뀌지 않아야 하는 것 (데이터, 명령행 출력 등)
    3. 추가하면 좋은 테스트
    4. 확인이 필요한 것 (예: 이름이 한 글자이거나 비어 있을 때)
    ```

4. 답을 검토합니다. 아래와 비슷하면 됩니다.
    - 바뀌는 곳: `build_site.py`(연락처 열과 예약자 표시), 테스트(새로), 필요하면 `README.md` 같은 문서
    - 바뀌지 않는 것: `data/reservations.json`의 데이터는 **그대로** 둡니다. 현황판에 보여 주는 방식만 바꿉니다. `python -m booking list` 출력도 그대로입니다.
5. 검토한 내용을 CR-001 이슈에 댓글로 남깁니다.

    ```text
    [영향 분석]
    - 바뀜: build_site.py (연락처 열 제거, 예약자 성+○○), 테스트 추가
    - 그대로: data/reservations.json(데이터는 지우지 않음), python -m booking 명령 출력
    - 확인 필요: (Copilot이 찾은 것 중 팀이 판단한 것)
    ```

확인: CR-001 이슈에 `[영향 분석]` 댓글이 있고, "데이터는 그대로"가 적혀 있습니다.

!!! warning "화면에서 가려도 원본은 공개되어 있습니다"
    이번 변경은 공개 현황판의 표시만 바꿉니다. Public 리포지토리의 `data/reservations.json` 원본은 그대로 보입니다. 오늘 데이터는 가짜라 괜찮지만, 실제 개인정보는 Public 리포지토리에 두면 안 됩니다.

!!! warning "데이터를 지우자는 제안이 나오면"
    Copilot이 "`reservations.json`에서 phone을 지우자"고 할 수 있습니다. 현업은 **현황판에 보이지 않게** 해 달라고 했지, 연락처 기록을 없애라고 하지 않았습니다. 요구를 넘어서는 변경은 받아들이지 않습니다.

## STEP 4. (개발자) 브랜치 `cr-001`에서 구현하기

1. 상태 표시줄 브랜치 이름 클릭 → **Create new branch...** → 이름 입력

    ```text
    cr-001
    ```

2. Chat **+**(**New Chat**) → Agent **Agent**를 고릅니다. **+**(**Add Context**)로 `build_site.py`를 추가합니다.
3. Chat에 붙여 넣기

    ```text
    변경 요청 CR-001을 구현해 주세요.
    - build_site.py가 만드는 현황판에서 연락처 열(머리글과 칸)을 없애 주세요.
    - 예약자는 성(첫 글자)과 "○○"로만 보여 주세요. 예: 김민수 → 김○○. 팀 이름은 괄호로 그대로 둡니다. 예: 김○○ (기획팀)
    - data/reservations.json과 booking 폴더의 코드는 바꾸지 마세요.
    - 예약자 표시를 확인하는 테스트를 tests/ 폴더에 추가하고 python -m pytest를 실행해 주세요.
    ```

4. 승인 요청을 읽고 승인합니다.
5. 소스 제어의 **Changes** 목록에서 바뀐 파일이 `build_site.py`와 테스트 파일뿐인지 봅니다.

확인: `data/reservations.json`과 `booking/` 폴더는 바뀌지 않았습니다.

## STEP 5. (개발자) 직접 확인하기

1. 터미널에서 실행합니다.

    === "Windows"

        ```bash
        python -m pytest
        ```

    === "Mac"

        ```bash
        python3 -m pytest
        ```

    === "Windows"

        ```bash
        python build_site.py
        ```

    === "Mac"

        ```bash
        python3 build_site.py
        ```

    ```text
    [완료] site/index.html 에 예약 5건을 썼습니다.
    ```

2. VS Code 탐색기에서 `site/index.html`을 오른쪽 클릭 → **Reveal in File Explorer**(Mac은 **Reveal in Finder**)를 클릭합니다.
3. 열린 폴더에서 `index.html`을 더블클릭해 브라우저로 엽니다.
4. 아래를 확인합니다.
    - 표 머리글에 **연락처**가 없습니다.
    - 예약자가 `김○○ (기획팀)`, `이○○ (서비스개발팀)`처럼 보입니다.
    - `010-`으로 시작하는 번호가 화면 어디에도 없습니다. 브라우저에서 ++ctrl+f++ (Mac ++cmd+f++)로 `010`을 찾아봅니다.

확인: 내 PC의 현황판에 연락처가 없고 예약자가 성과 ○○로 보입니다.

## STEP 6. PR, 병합, 자동 재배포 확인

1. (개발자) 커밋 메시지에 CR-001 이슈 번호를 넣어 커밋하고 **Publish Branch**를 클릭합니다.

    ```text
    CR-001 현황판에서 연락처 제거, 예약자 성+○○ 표시 (#번호)
    ```

2. (개발자) github.com에서 PR을 엽니다. 설명 끝에 `Closes #번호`를 넣습니다.
3. (BA) **Files changed**에서 이슈의 완료 기준 3개를 보고 **Approve**합니다.
4. (PM) **테스트 / test**가 초록인지 보고 병합합니다.
5. (모두) **Actions** 탭에서 **현황판 배포**가 다시 실행되어 초록이 되는 것을 봅니다. 아무도 배포 버튼을 누르지 않았습니다.
6. (모두) 현황판 주소를 강력 새로 고침합니다. Windows ++ctrl+shift+r++, Mac ++cmd+shift+r++

확인: 웹 주소의 현황판에서 연락처가 사라졌고, 예약자가 `김○○`처럼 보입니다. CR-001 이슈가 Closed입니다.

!!! tip "변경 요청 처리 흐름"
    요청 → 이슈(라벨 `변경요청`) → 영향 분석 → 브랜치 → 구현과 검증 → PR → 병합 → 자동 배포. 처음 기능을 만들 때와 같은 흐름입니다. 흐름이 같으니 요구가 바뀌어도 당황하지 않습니다.

## 다 됐는지 확인

- [ ] `[변경요청] CR-001` 이슈에 `변경요청` 라벨이 있다
- [ ] BA의 `[영향 분석]` 댓글에 바뀌는 파일과 "데이터는 그대로"가 있다
- [ ] `cr-001` 브랜치에서 `build_site.py`와 테스트만 바뀌었다
- [ ] 내 PC의 `site/index.html`에서 연락처가 없고 예약자가 `김○○`로 보였다
- [ ] 병합 뒤 **현황판 배포**가 자동으로 돌았고 웹 주소에도 반영됐다

## 막히면

??? failure "site/index.html이 탐색기에 안 보여요"
    `python build_site.py`를 먼저 실행해야 생깁니다. `site/`는 `.gitignore`에 있어 소스 제어에는 나오지 않는 것이 정상입니다.

??? failure "예약자가 김민수○○처럼 나와요"
    이름 전체 뒤에 ○○를 붙인 것입니다. 해당 줄을 선택하고 "성(첫 글자)만 남기고 ○○를 붙여 주세요"라고 요청합니다.

??? failure "웹 주소에서는 아직 연락처가 보여요"
    **Actions**에서 **현황판 배포**가 끝났는지 봅니다. 끝났다면 브라우저가 예전 페이지를 기억하는 것입니다. 강력 새로 고침합니다.

??? failure "Copilot이 reservations.json에서 phone을 지웠어요"
    요구를 넘은 변경입니다. **소스 제어**에서 그 파일을 **Discard Changes**로 되돌리고, "데이터는 바꾸지 말고 현황판 표시만 바꿔 주세요"라고 다시 요청합니다.

??? failure "Reveal in Finder 메뉴가 안 보여요"
    VS Code 아래쪽 터미널에서 Windows는 `start site\index.html`, Mac은 `open site/index.html`을 실행해도 브라우저로 열립니다.
