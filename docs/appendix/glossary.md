# 용어집

과정에서 나온 용어를 분류별로 정리했습니다. 처음 나온 실습을 괄호에 적었습니다.

## Copilot 사용 방식

| 용어 | 뜻 |
|---|---|
| **하네스**(Harness) | 언어 모델, 맥락, 도구를 조율하는 층입니다. Chat 보기에서 **+**(**New Chat**) 후 **Session Target**으로 고릅니다. **Copilot**(일상 작업에 권장, 기본), **Local**(VS Code 내장, 창을 닫으면 멈춤), Claude, Codex가 있습니다. (1-1) |
| **Session Target** | 새 채팅에서 하네스를 고르는 컨트롤입니다. 오늘은 **Copilot**을 기본으로, 프롬프트 파일을 쓸 때만 **Local**을 씁니다. (1-1) |
| **역할**(Agent 선택기) | 채팅이 어떤 방식으로 일할지 정합니다. **Ask**는 질문과 코드 설명(읽기 전용 도구만), **Agent**는 변경을 구현하고 검증합니다. 계획은 선택기가 아니라 `/plan` 명령으로 세웁니다. 목록에 다른 이름이 더 있으면 확장이 추가한 사용자 지정 에이전트입니다. Edit 역할은 없습니다. (1-1, 2교시) |
| **`/plan`** | Copilot 하네스에서 계획을 세우게 하는 명령입니다. Agent 선택기에는 없습니다. (4-1) |
| **Autopilot** | 역할이 아니라 Copilot 하네스의 모드입니다. 권한 수준 설정에도 같은 이름이 있습니다. |
| **권한**(Permissions) | 에이전트가 도구를 쓸 때 누가 승인할지 정합니다. **Manual**(기본, 내가 승인), Assisted, Allow all, Autopilot이 있습니다. 오늘은 Manual을 씁니다. (4-2) |
| **소스 제어 보기** | Git 변경 목록(**Changes**)과 diff를 보는 곳입니다. Windows ++ctrl+shift+g++, Mac ⌃⇧G. (4-2) |
| **Restore Checkpoint** | 이전 요청에 마우스를 올려 파일과 채팅 기록을 그 시점으로 되돌립니다. 터미널 명령, 네트워크 요청, 배포, 외부 서비스는 되돌리지 않습니다. (4-2) |
| **Steer with Message / Stop and Send** | 실행 중인 에이전트의 방향을 메시지로 조정하거나, 멈추고 새 요청을 보냅니다. 멈춰도 이미 한 작업은 그대로입니다. (4-2) |
| **슬래시 명령** | `/`로 시작하는 명령입니다. 오늘 쓴 것: `/plan`, `/explain`, `/fix`, `/tests`. 프롬프트 파일과 스킬도 `/이름`으로 부릅니다. |
| **`#codebase`** | 리포지토리 전체를 맥락으로 쓰게 하는 맥락 항목입니다. `#`을 치면 목록이 뜹니다. (1-3) |
| **Add Context** | 입력 칸의 **+** 버튼으로 파일과 폴더, 심볼, 이슈, PR을 맥락으로 붙입니다. 파일을 끌어다 놓아도 됩니다. (1-3) |
| **모델 Auto** | 적당한 모델을 자동으로 고릅니다. 모델 비용이 10% 할인됩니다. (1-1) |

## 제안과 채팅

| 용어 | 뜻 |
|---|---|
| **인라인 제안**(코드 완성) | 입력하는 자리에 회색 글씨로 나타나는 제안입니다. ++tab++으로 수락, ++esc++로 거절합니다. 유료 플랜에서 무제한이고 크레딧을 쓰지 않습니다. (2-1) |
| **NES**(Next Edit Suggestions, 다음 편집 제안) | 방금 고친 것에 이어서 다음에 고칠 곳을 제안합니다. 인라인 제안처럼 크레딧을 쓰지 않습니다. (2-1) |
| **인라인 채팅** | 편집기 안에서 바로 묻는 작은 채팅입니다. Windows ++ctrl+i++, Mac ++cmd+i++. 터미널에서도 됩니다. (2-2) |
| **Quick Chat** | 화면 위쪽에 잠깐 여는 채팅입니다. Windows ++ctrl+shift+alt+l++, Mac ⇧⌥⌘L. |

## 사용자 지정 파일

| 용어 | 뜻 |
|---|---|
| **지침 파일** | 모든 채팅에 항상 적용되는 규칙입니다. `.github/copilot-instructions.md` 또는 루트의 `AGENTS.md`. 적용됐는지는 응답의 **References**로 봅니다. (3-2, 7-3) |
| **대상 지정 지침** | `.github/instructions/*.instructions.md`. 머리말 `applyTo`로 특정 파일에만 적용합니다. |
| **프롬프트 파일** | 반복하는 요청을 파일로 저장한 것입니다. `.github/prompts/*.prompt.md`, 실행은 `/이름`. **Local 하네스에서만** 실행됩니다. (3-3) |
| **스킬** | `.github/skills/<이름>/SKILL.md`. 무엇을 하는지와 언제 쓰는지를 적어 두면 `/이름`으로 부르거나 요청이 맞을 때 자동으로 읽힙니다. 다른 하네스에서도 재사용할 수 있습니다. |
| **사용자 지정 에이전트** | `.github/agents/*.agent.md`. 역할 선택기에 내가 만든 에이전트가 함께 나옵니다. |
| **MCP** | Copilot에 외부 도구와 데이터를 연결하는 방법입니다. 명령 **MCP: Add Server**로 추가합니다. (7-3) |

## github.com의 Copilot

| 용어 | 뜻 |
|---|---|
| **Copilot 코드 리뷰** | PR의 **Reviewers**에서 Copilot을 요청하면 리뷰 댓글을 남깁니다. 승인이나 변경 요청이 아니라 댓글형입니다. AI Credits와 Actions 사용 시간을 씁니다. 1회 약 150크레딧(Balanced 기준). (6-1) |
| **PR 요약**(Summary) | PR 설명 칸의 Copilot 메뉴로 바뀐 내용을 요약합니다. Free에서는 안 됩니다. (4-3) |
| **클라우드 에이전트** | 이슈의 **Assignees**에 Copilot을 지정하면 GitHub 쪽에서 작업하고 항상 PR을 엽니다. (5-3) |
| **Copilot CLI** | 터미널에서 쓰는 Copilot입니다. `copilot`으로 실행합니다. (7-3) |

## 크레딧과 플랜

| 용어 | 뜻 |
|---|---|
| **AI Credits** | Copilot 사용량 단위입니다. 1크레딧은 0.01달러이고, Pro는 매월 1,500크레딧(기본 1,000 + 유연 500)입니다. 매월 1일 00:00 UTC 초기화, 이월 없음. Chat, 에이전트, 코드 리뷰, 클라우드 에이전트가 씁니다. |
| **Copilot status dashboard** | VS Code 상태 표시줄에서 월 사용량(%)을 보는 곳입니다. (1-1) |
| **콘텐츠 제외**(Content exclusion) | 특정 파일을 Copilot이 읽지 못하게 하는 기능입니다. Business, Enterprise 기능이고 Pro에는 없습니다. |
| **공개 코드 일치** | **Copilot settings**의 **Suggestions matching public code**에서 Allow 또는 Block을 고릅니다. 허용하면 일치한 출처와 라이선스를 보여 줍니다(코드 참조). (1-1) |
| **모델 학습 데이터 설정** | **Allow GitHub to use my data for AI model training**. Free, Pro, Pro+는 2026-04-24부터 기본으로 켜져 있습니다. 끄려면 Disabled. (1-1) |

## 프롬프트

| 용어 | 뜻 |
|---|---|
| **zero-shot** | 예시 없이 요청하는 것입니다. (3-1) |
| **few-shot** | 원하는 결과 예시를 한두 개 보여 주고 요청하는 것입니다. GitHub 문서 전략 "Give examples". (3-1) |
| **맥락**(Context) | Copilot이 답할 때 참고하는 파일, 대화, 지침입니다. 관련 맥락을 주고, 관련 없는 대화는 새 채팅으로 끊습니다. |
| **환각** | 근거 없이 그럴듯한 내용을 지어내는 것입니다. 예: 회의록에서 정하지 않은 "최대 3시간"을 정책처럼 쓰는 것. 근거를 요구하고 사람이 검토해 막습니다. (3-1, 5-1) |

## 개발과 협업

| 용어 | 뜻 |
|---|---|
| **HEAD, origin** | `HEAD`는 내가 지금 있는 커밋(보통 브랜치의 끝), `origin`은 GitHub 리포지토리의 별명입니다. `origin/main`은 GitHub에 있는 main입니다. (2-3) |
| **커밋 해시** | 커밋마다 붙는 고유 번호입니다. `f7a1c2e`처럼 앞 몇 자리만 줄여 씁니다. (2-3) |
| **브랜치** | main과 따로 작업하는 공간입니다. 오늘: `overlap-check`, `story-<번호>`, `add-pages`, `cr-001`. (4-1) |
| **PR**(Pull Request) | 브랜치의 변경을 main에 합쳐 달라는 요청입니다. 리뷰와 자동 검사가 여기서 일어납니다. (4-3) |
| **병합 충돌** | 두 브랜치가 같은 곳을 다르게 고쳐 자동으로 합칠 수 없는 상태입니다. 두 변경을 모두 남기도록 사람이 정리합니다. (6-1) |
| **사용자 스토리** | "누구로서, 무엇을 원한다, 왜냐하면" 형식의 요구입니다. 스토리 하나가 이슈 하나가 됩니다. (3-1, 5-1) |
| **인수 조건** | 스토리가 다 됐다고 판단하는 기준입니다. Given(상황), When(행동), Then(결과)으로 씁니다. (5-1) |
| **리팩터링** | 동작은 그대로 두고 코드를 읽기 쉽게 고치는 것입니다. GH-300 시험 범위에 있습니다. |
| **테스트**(pytest) | 코드가 기대대로 동작하는지 자동으로 확인하는 코드입니다. `python -m pytest`로 실행합니다. |
| **GitHub Actions** | 리포지토리에서 정해 둔 일을 자동으로 실행하는 GitHub 기능입니다. `.github/workflows/*.yml`에 적습니다. |
| **CI**(Continuous Integration, 지속적 통합) | 변경을 올릴 때마다 테스트를 자동으로 돌리는 것입니다. 오늘: `ci.yml` "테스트". (4-3) |
| **CD**(Continuous Deployment, 지속적 배포) | main에 병합될 때마다 결과물을 자동으로 내보내는 것입니다. 오늘: `pages.yml` "현황판 배포". (6-2) |
| **GitHub Pages** | 리포지토리의 웹페이지를 `https://아이디.github.io/리포지토리/` 주소로 무료 공개하는 기능입니다. 무료 계정은 Public 리포지토리에서 씁니다. (6-2) |
| **XSS**(Cross-Site Scripting) | 사용자가 입력한 글자에 섞인 스크립트를 웹페이지가 코드로 실행해 버리는 보안 문제입니다. `html.escape()`로 글자로 바꿔 막습니다. (7-2) |
| **CR**(Change Request, 변경 요청) | 진행 중에 들어온 요구 변경입니다. 오늘: CR-001 현황판 연락처 빼기. (6-3) |
