## 교안 { #lecture }

### 에이전트는 스스로 고치고, 실행하고, 확인합니다

에이전트는 일을 맡기면 스스로 계획을 세우고, 필요한 파일을 찾아 고치고, 테스트 같은 명령을 실행해서 결과를 확인해요. 테스트가 실패하면 원인을 보고 다시 고쳐요. 사람으로 치면 일을 받아서 끝까지 해 오는 동료예요. 하지만 동료가 해 온 일도 검토하듯이, 에이전트가 한 일도 우리가 검토해야 해요.

### 큰 일은 /plan 으로 계획부터 받습니다

큰 작업은 바로 고치게 하지 말고 /plan으로 계획부터 받아요. 계획을 보면 Copilot이 요구를 제대로 이해했는지 미리 알 수 있어요. 겹침 검사라면 세 가지를 봐요. 같은 회의실, 같은 날짜끼리만 비교하는지, 10시에서 11시 예약 다음에 11시에서 12시 예약은 맞닿을 뿐 겹치는 게 아니라는 걸 아는지, 그리고 테스트에 이런 경우가 다 들어 있는지예요. 계획이 틀렸으면 지금 고치는 게 가장 싸요.

### 권한은 Manual: 실행 전에 내가 읽고 승인합니다

오늘 권한은 Manual이에요. 에이전트가 도구를 쓰거나 터미널 명령을 실행하려고 하면 승인 요청이 떠요. 무작정 다 승인하지 말고 무엇을 하려는지 읽어요. python -m pytest처럼 테스트를 돌리는 건 승인해도 돼요. 반대로 파일을 지우는 rm이나 del, 무언가를 설치하거나 밖으로 보내는 명령은 멈추고 확인해요. 모르겠으면 Stop을 누르고 물어보세요. 설정에 따라 읽기만 하는 명령은 자동으로 승인되고, rm, del은 항상 승인이 필요해요.

### 바뀐 것은 Changes에서 검토하고, 아니면 되돌립니다

에이전트가 일을 마치면 채팅에 바뀐 파일과 몇 줄이 바뀌었는지가 보여요. 눌러서 보거나, Changes 패널을 열어 파일별로 검토해요. 특정 부분이 마음에 안 들면 diff에서 그 부분을 선택하고 고칠 점을 말하면 돼요. 아예 처음부터 다시 하고 싶으면 이전 요청에 마우스를 올려 Restore Checkpoint를 눌러요. 파일과 채팅이 그 시점으로 돌아가요. 단, 이미 실행한 터미널 명령이나 외부로 보낸 것까지 되돌리지는 않아요.

### 테스트는 경계에서 틀립니다

버그는 대부분 경계에서 생겨요. 10시에서 11시 예약이 있을 때 10시 반 시작은 당연히 겹치지만, 11시 시작은 끝과 시작이 맞닿을 뿐 겹치지 않아요. 부등호 하나를 잘못 쓰면 11시 예약까지 막혀요. 2교시에 고친 18시 버그도 같은 종류였죠. 그래서 테스트는 이런 경계를 꼭 넣어요. /tests로 Copilot에게 경계값 테스트를 더 만들어 달라고 할 수 있어요. 하지만 어떤 경우를 테스트할지 정하고, 그 테스트가 정말 맞는 내용인지 읽는 건 사람의 몫이에요.

### PR을 열면 테스트가 자동으로 돕니다

고친 걸 커밋하고 push한 다음 github.com에서 PR을 열어요. PR 설명은 Copilot 메뉴의 Summary로 자동 요약을 받을 수 있어요. PR이 열리면 Starter에 들어 있는 테스트 워크플로가 자동으로 돌아요. 초록 체크면 병합하고, 빨간 X면 Details에서 어떤 테스트가 실패했는지 보고 그 내용을 Copilot에게 붙여서 고쳐요. 이게 1교시에 말한 CI예요.

### 오후에는 팀이 같은 서비스를 함께 만듭니다

| 역할 | 결정하고 정리하는 일 | Copilot에게 시키는 일 |
|---|---|---|
| PO | 무엇부터 할지, 정책 결정 | 요청과 회의록으로 우선순위 초안 |
| PM | 이슈 만들고 사람에게 배분, 병합 | 스토리별 바뀔 파일과 충돌 위험 정리 |
| BA | 인수 조건 확정, 결과 검토 | /story 로 인수 조건 초안 |
| 개발자 | 기술 검토, 배포 설정 | 영향 분석, 배포 워크플로 |
| 모두 | 스토리 하나씩 구현 | 에이전트로 구현, 테스트 |

오후에는 3명에서 4명이 한 팀이 돼요. 역할은 PO, PM, BA, 개발자예요. 역할은 무엇을 결정하고 정리하고 검토하느냐의 차이예요. PO는 무엇부터 할지와 정책을 정하고, PM은 이슈를 만들어 사람에게 나누고, BA는 인수 조건을 확정하고, 개발자는 기술 검토와 배포 설정을 맡아요. 그리고 중요한 건 맨 아래 줄이에요. 구현은 모두가 해요. 각자 스토리 하나씩 맡아 에이전트로 구현해요. 개발 경험이 없어도 오전에 한 그대로 하면 돼요. 3인 팀은 PO가 PM을 겸해요.
