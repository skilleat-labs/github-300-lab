# 실습 4-2. 에이전트로 구현하고 테스트

!!! abstract "이 실습에서 할 일"
    - 4-1에서 고친 계획대로 **Agent** 역할에게 구현과 테스트 추가를 맡깁니다.
    - 도구와 터미널 명령 승인 요청을 읽고 승인하며, 바뀐 코드를 **Changes** 패널에서 검토합니다.
    - 테스트와 실제 명령으로 직접 검증하고, 경계값 테스트를 더 받은 뒤 커밋합니다.

**소요 시간** 약 12분  **실습 장소** 개인 리포지토리 `room-practice`, 브랜치 `overlap-check`  **관련 교안** [4교시 교안](index.md)

## 준비

- 상태 표시줄 브랜치 이름이 `overlap-check`인지 봅니다.
- 4-1의 계획 채팅이 열려 있어야 합니다. 닫았다면 Chat 보기 위쪽 채팅 목록에서 다시 엽니다.

## STEP 1. Agent 역할로 구현 요청하기

1. 계획 채팅의 입력 칸 아래 Agent 선택기를 클릭하고 **Agent**를 고릅니다. Session Target은 **Copilot** 그대로 둡니다.
2. Chat에 붙여 넣기

    ```text
    위에서 고친 계획대로 구현해 주세요.
    - booking/rules.py의 validate()에서 TODO 자리에 겹침 검사를 넣어 주세요.
    - tests/test_rules.py에 계획의 테스트를 추가해 주세요. 기존 테스트 4개는 그대로 두세요.
    - 다 되면 python -m pytest를 실행해서 결과를 보여 주세요.
    - 계획에 없는 파일은 바꾸지 마세요.
    ```

3. ++enter++를 누릅니다.

확인: 채팅에 Copilot이 파일을 읽고 고치는 과정이 하나씩 나타납니다.

!!! tip "실행 중에 방향을 바꾸고 싶으면"
    입력 칸 오른쪽 Send 드롭다운에서 **Steer with Message**(진행 중에 메시지로 조정)를 쓰면 멈추지 않고 방향을 바꿀 수 있습니다. **Stop and Send**는 멈추고 새 요청을 보냅니다. 멈춰도 이미 한 작업은 되돌려지지 않습니다.

## STEP 2. 승인 요청 읽고 승인하기

권한이 **Manual**이라 Copilot이 터미널 명령을 실행하거나 도구를 쓰기 전에 채팅에 승인을 묻습니다.

1. 승인 요청이 뜨면 **무엇을 실행하려는지** 먼저 읽습니다.
2. 아래 표로 판단합니다.

    | 승인 요청 내용 | 판단 |
    |---|---|
    | `python -m pytest` 실행 | 승인. 테스트를 돌리는 것입니다 |
    | 파일 읽기, 검색 | 승인 |
    | `pip install ...` 실행 | 무엇을 설치하는지 보고 판단. pytest면 괜찮습니다 |
    | `rm`, `del` 같은 삭제 명령, `git push` | 승인하지 않습니다. 요청 내용을 다시 확인합니다 |

3. 괜찮으면 승인 버튼을 누릅니다.

확인: 채팅에 테스트 실행 결과가 나오고, `passed`가 보입니다.

!!! warning "승인은 내 책임입니다"
    **Restore Checkpoint**로 파일은 되돌릴 수 있지만, 이미 실행한 터미널 명령과 네트워크 요청은 되돌릴 수 없습니다. 읽지 않고 승인하지 않습니다.

## STEP 3. 바뀐 내용 검토하기

1. 채팅 답 아래에 바뀐 파일 목록과 diff 통계(추가, 삭제 줄 수)가 보입니다. `booking/rules.py`를 클릭합니다.
2. 빨간 줄(지운 것)과 초록 줄(추가한 것)을 읽습니다.
3. **Changes** 패널을 엽니다. Windows는 ++ctrl+shift+g++, Mac은 ⌃⇧G(++ctrl+shift+g++)
4. 바뀐 파일이 `booking/rules.py`, `tests/test_rules.py` 두 개뿐인지 봅니다.
5. 아래 기준으로 코드를 읽습니다. 코드를 다 이해하지 못해도 됩니다. 단어를 찾아보며 읽습니다.

    | 찾을 것 | 있으면 됩니다 |
    |---|---|
    | 같은 회의실 | `room_id ==` |
    | 같은 날짜 | `date ==` |
    | 자기 자신 제외 | `id !=` |
    | 겹침 판단 | `start <` 와 `<`로 이어지는 두 비교. `<=`면 맞닿은 시간이 겹침으로 처리되어 틀립니다 |
    | 오류 메시지 | `이미 예약된 시간입니다` |

확인: 바뀐 파일이 두 개이고, 위 표의 다섯 가지를 찾았습니다.

!!! tip "모르는 줄은 그 자리에서 물어보세요"
    diff에서 이해가 안 되는 줄을 드래그로 선택하고, 채팅에 "선택한 부분을 쉽게 설명해 주세요"라고 물어봅니다. 고치고 싶으면 선택한 채로 "이 메시지를 '이미 예약된 시간입니다: #번호 시작~끝 제목' 형식으로 바꿔 주세요"처럼 요청합니다.

## STEP 4. 마음에 안 들면 되돌리기 (필요할 때만)

Copilot이 계획에 없는 파일을 바꿨거나 방향이 틀렸다면 처음부터 다시 시킵니다.

1. 채팅에서 방금 보낸 구현 요청 위에 마우스를 올립니다.
2. **Restore Checkpoint**(체크포인트로 되돌리기)를 클릭합니다.
3. 파일과 채팅이 요청 전으로 돌아갑니다. 요청 문장을 고쳐 다시 보냅니다.

확인: 되돌린 경우 **Changes** 패널에 바뀐 파일이 없습니다. 되돌리지 않은 경우 이 STEP은 건너뜁니다.

## STEP 5. 직접 검증하기

Copilot이 "통과했습니다"라고 말해도 내 눈으로 한 번 더 봅니다.

1. 위쪽 메뉴 **Terminal** → **New Terminal**로 터미널을 엽니다.
2. 테스트를 실행합니다.

    ```text
    python -m pytest
    ```

    `4 passed`보다 숫자가 늘었고 `failed`가 없으면 됩니다. 예: `7 passed`

3. 겹치는 예약을 직접 넣어 봅니다.

    ```text
    python -m booking add --room R1 --title 겹침 --date 2026-11-10 --start 10:30 --end 11:30 --booker 홍길동 --attendees 2
    ```

    이런 결과가 나오면 됩니다. 메시지 문장은 조금 다를 수 있습니다.

    ```text
    [예약 실패]
     - 이미 예약된 시간입니다: #1 10:00~11:00 주간 업무 회의
    ```

4. 맞닿은 시간을 넣어 봅니다.

    ```text
    python -m booking add --room R1 --title 이어서 --date 2026-11-10 --start 11:00 --end 12:00 --booker 홍길동 --attendees 2
    ```

    ```text
    [예약 완료] #6 2026-11-10 11:00~12:00 R1 이어서
    ```

    번호(`#6`)는 다를 수 있습니다.

5. 방금 넣은 예약을 되돌립니다. 왼쪽 활동 막대의 **소스 제어** 아이콘을 클릭하고, `data/reservations.json` 오른쪽 되돌리기 아이콘(**Discard Changes**)을 클릭하고 확인합니다.

확인: 겹치는 예약은 실패, 맞닿은 예약은 성공했고, `data/reservations.json` 변경이 사라졌습니다.

!!! warning "데이터 변경은 커밋하지 않습니다"
    `add`를 실행하면 `data/reservations.json`이 바뀝니다. 실습용 예약이 커밋에 섞이지 않게 꼭 **Discard Changes**로 되돌립니다.

## STEP 6. `/tests`로 경계값 테스트 더 받기

1. `tests/test_rules.py`를 엽니다.
2. Chat에 붙여 넣기

    ```text
    /tests booking/rules.py의 겹침 검사에 대한 경계값 테스트를 tests/test_rules.py에 더 추가해 주세요.
    - 같은 시간이지만 다른 회의실(R2)이면 통과
    - 같은 시간이지만 다른 날짜(2026-11-11)이면 통과
    - 기존 예약을 완전히 감싸는 예약(09:30~11:30)은 실패
    - 이미 있는 테스트와 겹치는 것은 추가하지 마세요.
    ```

3. 승인 요청이 뜨면 STEP 2처럼 읽고 승인합니다.
4. 터미널에서 다시 실행합니다.

    ```text
    python -m pytest
    ```

확인: 통과한 테스트 수가 STEP 5보다 늘었고 `failed`가 없습니다.

## STEP 7. 커밋하기

1. 왼쪽 활동 막대의 **소스 제어** 아이콘을 클릭합니다.
2. **Changes** 아래에 `booking/rules.py`, `tests/test_rules.py`만 있는지 봅니다. `data/reservations.json`이 있으면 **Discard Changes**로 되돌립니다.
3. 메시지 칸에 입력합니다.

    ```text
    같은 회의실, 같은 날짜의 겹치는 예약 막기 (현업 요청 1번)
    ```

4. **Commit**(커밋)을 클릭합니다. "스테이징할 변경이 없다"는 창이 뜨면 **Yes**(모두 스테이징하고 커밋)를 누릅니다.

확인: 소스 제어의 변경 목록이 비었고, 버튼이 **Publish Branch**로 바뀌었습니다.

## 다 됐는지 확인

- [ ] **Agent** 역할로 계획대로 구현을 받았다
- [ ] 승인 요청을 읽고 승인했다
- [ ] **Changes** 패널에서 바뀐 파일이 `rules.py`, `test_rules.py` 두 개인 것을 확인했다
- [ ] `python -m pytest`가 모두 통과한다
- [ ] 10:30~11:30은 실패, 11:00~12:00은 성공하는 것을 직접 봤다
- [ ] `data/reservations.json` 변경을 되돌렸다
- [ ] `overlap-check` 브랜치에 커밋했다

## 막히면

??? failure "테스트가 failed로 나와요"
    채팅에 터미널 결과를 붙여 넣고 "이 테스트가 실패하는 이유를 설명하고 고쳐 주세요"라고 요청합니다. 테스트를 지우거나 기대값을 바꿔서 통과시키려 하면 승인하지 말고 "테스트는 그대로 두고 코드를 고쳐 주세요"라고 다시 요청합니다.

??? failure "11:00~12:00도 이미 예약된 시간이라고 실패해요"
    겹침 판단에 `<=`가 쓰였을 가능성이 큽니다. `rules.py`에서 그 줄을 선택하고 "끝과 시작이 맞닿으면 겹침이 아닙니다. 이 비교를 고쳐 주세요"라고 요청합니다.

??? failure "10:30~11:30이 [예약 완료]로 나와요"
    구현이 아직 저장되지 않았거나 다른 브랜치일 수 있습니다. 상태 표시줄이 `overlap-check`인지, `rules.py` 탭에 저장 안 됨 표시(흰 점)가 없는지 봅니다. 그다음 **Discard Changes**로 데이터를 되돌리고 다시 실행합니다.

??? failure "python을 찾을 수 없다고 나와요 (Mac)"
    `python` 대신 `python3`로 실행합니다. 예: `python3 -m pytest`

??? failure "Copilot이 README나 다른 파일도 바꿨어요"
    **소스 제어**에서 그 파일 오른쪽 되돌리기 아이콘(**Discard Changes**)으로 그 파일만 되돌립니다. 전체가 마음에 안 들면 STEP 4의 **Restore Checkpoint**를 씁니다.
