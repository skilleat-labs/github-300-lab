# 실습 3-1. 회의록에서 사용자 스토리 뽑기

!!! abstract "이 실습에서 할 일"
    - 같은 회의록으로 **zero-shot**(예시 없이)과 **few-shot**(예시 1개 포함) 프롬프트를 비교합니다.
    - Copilot이 회의록에서 **결정하지 못한 정책**을 마음대로 정하지 않았는지 검토합니다.
    - 결과를 `docs/03_사용자스토리.md`로 저장하고 커밋합니다.

    **예상 시간** 12분 (짧게 합니다)

!!! info "사용자 스토리와 인수 조건이 뭔가요?"
    **사용자 스토리**는 기능 요구를 사용자 입장에서 한 문장으로 쓴 것입니다. 형식은 "〈누구〉로서, 〈무엇〉을 원한다. 왜냐하면 〈이유〉이기 때문이다."입니다.

    | 회의록의 결정 | 사용자 스토리로 바꾸면 |
    |---|---|
    | 겹치는 예약을 막는다 | 회의실을 예약하는 **직원으로서**, 이미 예약된 시간에는 **예약이 안 되기를 원한다**. 회의실 앞에서 누가 먼저 예약했는지 **다투지 않기 위해서**이다. |

    **인수 조건**은 그 스토리가 다 됐는지 판단하는 기준입니다. 확인할 수 있는 예로 씁니다.

    - 10:00~11:00 예약이 있으면 10:30~11:30은 "이미 예약된 시간"으로 실패
    - 11:00~12:00은 성공 (끝과 시작이 맞닿는 것은 겹침이 아님)

    "겹침 검사 구현"이라고만 쓰면 누구를 위한 일인지, 어디까지 하면 끝인지가 빠집니다. 스토리와 인수 조건으로 쓰면 만드는 사람과 검토하는 사람이 같은 기준으로 확인합니다. 오후에는 이것을 이슈로 만들어 나눠 구현합니다.

## 준비

- `room-practice`가 열려 있고, Chat은 Session Target **Copilot**, 역할 **Ask**, 모델 **Auto**입니다.
- `docs/01_킥오프_회의록.md`를 한 번 훑어봅니다. 특히 **결정한 것** 4개와 **결정하지 못한 것** 3개를 봐 둡니다.

## STEP 1. zero-shot: 예시 없이 요청하기

1. **+**(**New Chat**)로 새 채팅을 엽니다. 역할 **Ask**.
2. 탐색기에서 `docs/01_킥오프_회의록.md`를 Chat 입력 칸에 끌어다 놓습니다.
3. Chat에 붙여 넣고 Enter를 누릅니다.

    ```text
    첨부한 회의록을 사용자 스토리로 정리해 주세요.
    ```

확인: 사용자 스토리 목록이 나옵니다. 형식(표, 목록, 문장)과 개수는 사람마다 다릅니다.

## STEP 2. few-shot: 예시 1개를 주고 요청하기

1. 새 채팅(**+**)을 열고 같은 회의록을 다시 첨부합니다.
2. Chat에 붙여 넣고 Enter를 누릅니다.

    ```text
    첨부한 회의록의 "결정한 것"을 사용자 스토리로 정리해 주세요. 아래 예시와 같은 형식으로 써 주세요.

    ### S1. 겹치는 예약 막기
    - 스토리: 예약하는 직원으로서, 같은 회의실 같은 시간에 이미 예약이 있으면 예약이 안 되기를 원한다. 회의실 앞에서 다투지 않기 위해서다.
    - 인수 조건:
      - 10:00~11:00 예약이 있으면 10:30~11:30 예약은 "이미 예약된 시간"으로 실패한다.
      - 11:00~12:00 예약은 성공한다(끝과 시작이 맞닿는 것은 겹침이 아니다).
    ```

3. STEP 1의 답과 나란히 비교합니다.

확인: few-shot 답은 모든 스토리가 **같은 형식**(스토리 한 줄 + 인수 조건 목록)으로 나옵니다. zero-shot보다 고르게 정리되었으면 됩니다.

!!! tip "few-shot이 효과 있는 이유"
    GitHub의 프롬프트 작성 전략 중 **Give examples**(예시를 준다)입니다. 원하는 결과 모양을 말로 설명하는 것보다 하나 보여 주는 편이 빠르고 정확합니다.

## STEP 3. Copilot이 정하지 않은 것을 정했는지 검토하기

회의록의 **결정하지 못한 것**은 아래 3가지입니다.

| 결정하지 못한 것 | 회의록의 의견 |
|---|---|
| 한 번에 예약할 수 있는 최대 시간 | 2시간 vs 4시간 |
| 노쇼 자동 취소 기준 시간과 범위 | 10분 vs 15분, 이번 범위에 넣을지 |
| 현황판에 연락처를 보여 줄지 | 확인 필요 |

1. STEP 1, 2의 답에서 "최대 2시간", "최대 4시간", "10분 후 자동 취소", "15분 후 자동 취소", "연락처 표시" 같은 내용을 찾습니다.
2. 이런 내용이 **확정된 요구처럼** 들어가 있는지 표시합니다.

확인: 하나라도 확정처럼 들어가 있으면, Copilot이 회의록에 없는 정책을 지어낸 것(**환각**)입니다. 사람이 검토하지 않으면 정해지지 않은 정책이 그대로 개발로 넘어갑니다.

## STEP 4. 규칙을 넣어 다시 요청하기

1. 같은 채팅(STEP 2)에 이어서 붙여 넣고 Enter를 누릅니다.

    ```text
    다시 정리해 주세요. 규칙:
    1. 회의록의 "결정한 것" 4개만 사용자 스토리로 만든다.
    2. 회의록에 없는 정책은 정하지 말고 "확인 필요"로 표시한다.
    3. "결정하지 못한 것"은 스토리로 만들지 말고, 맨 아래 "확인 필요" 목록에 누가 정해야 하는지와 함께 적는다.
    4. "이번 범위가 아닌 것"은 넣지 않는다.
    ```

확인: 스토리가 4개(겹침, 정원, 현황판, 취소)이고, 맨 아래 "확인 필요"에 최대 예약 시간, 노쇼 기준, 연락처 공개가 들어 있습니다. 최대 시간 담당자로 강도윤 팀장이 적혀 있으면 더 좋습니다.

## STEP 5. Agent에게 파일로 저장시키기

1. 역할 선택기를 **Agent**로 바꿉니다.
2. Chat에 붙여 넣고 Enter를 누릅니다.

    ```text
    바로 앞의 마지막 답(사용자 스토리 4개와 확인 필요 목록)을 docs/03_사용자스토리.md 파일로 저장해 주세요. 맨 위 제목은 "# 회의실 예약 서비스 사용자 스토리"로 해 주세요. 다른 파일은 바꾸지 마세요.
    ```

3. 만들어진 `docs/03_사용자스토리.md`를 클릭해 열고 내용을 훑어봅니다.

확인: 탐색기의 `docs` 폴더에 `03_사용자스토리.md`가 생겼고, 스토리 4개와 "확인 필요" 목록이 들어 있습니다.

## STEP 6. 커밋하기

1. 소스 제어(Windows `Ctrl+Shift+G`, Mac `⌃⇧G`)를 엽니다.
2. **Changes**에 `03_사용자스토리.md`만 있는지 확인합니다.
3. 메시지 칸에 아래를 입력하고 **Commit**을 누릅니다. 스테이징을 묻는 창이 뜨면 **Yes**를 누릅니다.

    ```text
    킥오프 회의록으로 사용자 스토리 정리
    ```

4. **Sync Changes**를 누릅니다.

확인: **Changes**가 비고, github.com의 `room-practice`에서 `docs/03_사용자스토리.md`가 보입니다.

## 다 됐는지 확인

- [ ] zero-shot과 few-shot 결과의 형식 차이를 봤습니다.
- [ ] Copilot이 "결정하지 못한 것"을 확정처럼 썼는지 검토했습니다.
- [ ] "확인 필요" 규칙을 넣어 다시 받았습니다.
- [ ] `docs/03_사용자스토리.md`를 커밋하고 GitHub에 올렸습니다.

## 막히면

!!! tip "먼저 Copilot과 함께 해결합니다"
    오류 메시지나 막힌 상황을 Chat(Ask)에 붙여 넣고 원인과 해결 순서를 묻습니다. 아래는 자주 막히는 경우입니다. 묻는 방법은 [막혔을 때](../setup/3-troubleshooting.md#copilot)에 있습니다.

??? failure "Copilot이 스토리를 10개 넘게 만듭니다"
    "결정한 것 4개만"이라는 조건이 빠진 경우입니다. STEP 4의 규칙을 그대로 붙여 넣어 다시 요청합니다.

??? failure "확인 필요 목록이 비어 있습니다"
    회의록이 첨부되지 않았을 수 있습니다. 입력 칸 위에 `01_킥오프_회의록.md`가 붙어 있는지 확인하고, 없으면 다시 끌어다 놓습니다.

??? failure "Agent가 파일을 만들지 않고 내용만 보여 줍니다"
    역할이 **Ask**입니다. 역할 선택기에서 **Agent**를 고르고 STEP 5를 다시 요청합니다.

??? failure "다른 파일까지 바뀌었습니다"
    Chat에서 STEP 5 요청에 마우스를 올리고 **Restore Checkpoint**를 누른 뒤 다시 요청합니다. 또는 소스 제어에서 바뀐 다른 파일만 **Discard Changes**합니다.
