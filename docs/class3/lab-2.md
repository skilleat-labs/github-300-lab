# 실습 3-2. 지침 파일 만들기

!!! abstract "이 실습에서 할 일"
    - 리포지토리에 **지침 파일** `.github/copilot-instructions.md`를 만듭니다.
    - 지침 파일이 없을 때와 있을 때, 같은 질문에 대한 Copilot 답을 비교합니다.
    - 응답의 **References**에서 지침 파일이 실제로 쓰였는지 확인하고 커밋합니다.

    **예상 시간** 약 12분

## 지침 파일이란

매번 프롬프트에 "한국어로 답해 줘", "회의록에 없는 정책은 지어내지 마"를 붙이기는 번거롭습니다. **지침 파일**(custom instructions)에 한 번 써 두면 이 리포지토리의 모든 채팅에 자동으로 함께 들어갑니다.

| 파일 | 위치 | 적용 범위 |
|---|---|---|
| `.github/copilot-instructions.md` | 리포지토리 | 이 리포지토리의 모든 채팅 (오늘 만들 것) |
| `AGENTS.md` | 리포지토리 루트 | 위와 같은 용도의 다른 이름 |
| `~/.copilot/copilot-instructions.md` | 내 PC | 나 혼자, 모든 프로젝트 |

리포지토리에 넣고 커밋하면 **팀 전체가 같은 지침**을 씁니다.

## STEP 1. 지침 파일 없이 먼저 물어보기 (전)

1. Chat에서 **+**(**New Chat**)로 새 채팅을 엽니다. Session Target **Copilot**, 역할 **Ask**, 모델 **Auto**.
2. Chat에 붙여 넣고 Enter를 누릅니다.

    ```text
    한 번에 너무 오래 예약하지 못하게 최대 예약 시간 검사를 booking/rules.py에 넣으려고 합니다. 어떻게 바꾸면 되는지 알려 주세요.
    ```

3. 답에서 아래 두 가지를 메모해 둡니다.
    - 최대 시간을 몇 시간으로 정했나요? (2시간, 4시간 등)
    - 답이 한국어인가요, 오류 메시지 문장은 한국어인가요?

확인: 메모를 했습니다. 대부분 최대 시간을 **스스로 정해서** 코드를 보여 줍니다. 회의록에서는 아직 정하지 못한 정책인데도요.

## STEP 2. 지침 파일 만들기

1. 왼쪽 탐색기에서 `.github` 폴더를 마우스 오른쪽 버튼으로 클릭합니다. (`workflows` 폴더가 들어 있는 그 폴더입니다.)
2. **New File...**을 고릅니다.
3. 파일 이름에 아래를 입력하고 Enter를 누릅니다.

    ```text
    copilot-instructions.md
    ```

확인: 탐색기에 `.github/copilot-instructions.md`가 생기고 빈 편집기가 열렸습니다. `.github` 폴더 바로 아래에 있어야 하고, `workflows` 폴더 안에 들어가면 안 됩니다.

!!! tip "명령으로 만드는 방법"
    명령 팔레트(Windows `Ctrl+Shift+P`, Mac `⇧⌘P`)에서 **Chat: New Instructions File**을 실행해도 됩니다. 위치를 묻는 화면이 나오면 이 리포지토리의 `.github` 폴더를 고릅니다.

    !!! note "화면이 조금 다를 수 있어요"
        명령이 묻는 순서와 선택지는 VS Code 버전에 따라 다릅니다. 헷갈리면 위 STEP 2의 탐색기 방법으로 만듭니다.

## STEP 3. 지침 내용 쓰기

1. 아래 내용을 통째로 복사해 `copilot-instructions.md`에 붙여 넣습니다.

    ```markdown
    # 회의실 예약 서비스 Copilot 지침

    ## 프로젝트
    - 사내 회의실 예약 서비스다. 공유 엑셀 예약을 대신한다.
    - 요구사항의 근거는 docs/ 폴더의 문서다. 현업 요청(00), 킥오프 회의록(01), 현행 업무(02), 사용자 스토리(03).
    - 예약 규칙 검사는 booking/rules.py의 validate()에 모은다.

    ## 답변
    - 답변은 한국어로 한다.
    - 이 리포지토리를 읽는 사람은 기획자와 운영 담당자가 많다. 전문 용어는 처음 나올 때 쉬운 말로 풀어 쓴다.

    ## 정책
    - 회의록이나 docs/ 문서에 없는 정책(최대 예약 시간, 노쇼 기준, 연락처 공개 등)은 지어내지 않는다. 정해지지 않았다고 알리고, 누구에게 확인해야 하는지 질문한다.
    - 운영 시간은 09:00~18:00이고 18:00에 끝나는 예약은 가능하다. 예약은 30분 단위다.

    ## 코드
    - Python 3.12 기준으로 작성한다.
    - 사용자에게 보이는 오류 메시지는 한국어 문장으로, 마침표로 끝낸다. 예: "정원을 넘었습니다."
    - 기능을 바꾸면 pytest 테스트를 tests/ 폴더에 함께 추가한다. 테스트 함수 이름은 한국어로 동작을 설명한다. 예: test_정원을_넘으면_막는다
    - 바꾼 뒤에는 python -m pytest로 확인한다.

    ## 하지 말 것
    - data/reservations.json, data/rooms.json은 사용자가 요청할 때만 바꾼다.
    - 요청받지 않은 파일은 고치지 않는다.
    ```

2. 저장합니다(Windows `Ctrl+S`, Mac `⌘S`).

확인: 편집기 탭의 파일 이름 옆 동그라미(저장 안 됨 표시)가 사라졌습니다.

!!! tip "지침은 짧고 구체적으로"
    지침 파일은 모든 채팅에 함께 들어갑니다. 길게 쓰면 맥락을 차지하고, 애매하게 쓰면 지켜지지 않습니다. "좋은 코드를 써라"보다 "오류 메시지는 한국어 문장으로, 마침표로 끝낸다"처럼 확인할 수 있게 씁니다.

## STEP 4. 새 채팅에서 같은 질문하기 (후)

지침은 **새 채팅**부터 적용됩니다.

1. **+**(**New Chat**)로 새 채팅을 엽니다. 역할 **Ask**.
2. STEP 1과 **똑같은** 질문을 붙여 넣고 Enter를 누릅니다.

    ```text
    한 번에 너무 오래 예약하지 못하게 최대 예약 시간 검사를 booking/rules.py에 넣으려고 합니다. 어떻게 바꾸면 되는지 알려 주세요.
    ```

3. 답에서 **References**(참조) 부분을 펼칩니다.

확인: **References** 목록에 `copilot-instructions.md`가 보입니다. 이것이 지침 파일이 이번 답에 들어갔다는 증거입니다.

## STEP 5. 전과 후 비교하기

STEP 1에서 메모한 것과 비교합니다.

| 비교 | 지침 없음 (STEP 1) | 지침 있음 (STEP 4) |
|---|---|---|
| 최대 시간 | 스스로 정한 숫자 | "아직 정해지지 않았다", "강도윤 팀장에게 확인" 같은 질문 |
| 오류 메시지 | 영어이거나 제각각 | 한국어 문장 |
| 테스트 | 언급 없음 | tests/에 pytest 테스트를 추가하자는 내용 |

확인: STEP 4의 **References**에 지침 파일이 있고, 답이 최대 시간을 지어내지 않았습니다. 지침 없이도 답이 적절했다면 차이가 없어도 정상입니다. 차이를 만들려고 다시 시도하지 않습니다.

!!! warning "지침은 '항상 지키는 규칙'이 아닙니다"
    지침 파일은 Copilot에게 주는 강한 힌트이지, 반드시 지키는 잠금장치가 아닙니다. 중요한 규칙은 사람의 검토와 테스트로 한 번 더 확인합니다.

## STEP 6. 커밋하기

1. 소스 제어(Windows `Ctrl+Shift+G`, Mac `⌃⇧G`)를 엽니다.
2. **Changes**에 `copilot-instructions.md`만 있는지 확인합니다.
3. 메시지 칸에 아래를 입력하고 **Commit**, 이어서 **Sync Changes**를 누릅니다.

    ```text
    Copilot 지침 파일 추가
    ```

확인: github.com의 `room-practice`에서 `.github/copilot-instructions.md`가 보입니다.

## 다 됐는지 확인

- [ ] `.github/copilot-instructions.md`가 `.github` 바로 아래에 있습니다.
- [ ] 새 채팅의 **References**에서 지침 파일을 확인했습니다.
- [ ] 같은 질문에 대해 지침 전과 후의 답을 비교했습니다.
- [ ] 지침 파일을 커밋하고 GitHub에 올렸습니다.

## 막히면

!!! tip "먼저 Copilot과 함께 해결합니다"
    오류 메시지나 막힌 상황을 Chat(Ask)에 붙여 넣고 원인과 해결 순서를 묻습니다. 아래는 자주 막히는 경우입니다. 묻는 방법은 [막혔을 때](../setup/3-troubleshooting.md#copilot)에 있습니다.

??? failure "References에 지침 파일이 보이지 않습니다"
    1. 파일 위치가 `.github/copilot-instructions.md`인지 확인합니다. `.github/workflows/` 안에 만들었으면 탐색기에서 끌어 `.github` 폴더로 옮깁니다.
    2. 파일 이름의 철자(`copilot-instructions.md`, s 포함)를 확인합니다.
    3. 파일을 저장했는지 확인합니다.
    4. 기존 채팅이 아니라 **새 채팅**에서 물어야 합니다.

??? failure "탐색기에 .github 폴더가 안 보입니다"
    탐색기 맨 위에 `ROOM-PRACTICE`가 보이는지 확인합니다. 다른 폴더를 열었다면 **File** → **Open Folder**로 `room-practice`를 엽니다.

??? failure "지침을 넣었는데도 최대 시간을 정해 버립니다"
    Copilot 답은 매번 다릅니다. 새 채팅에서 한 번 더 물어봅니다. 그래도 같으면 지침의 "정책" 문장을 더 구체적으로 고칩니다. 예: "최대 예약 시간은 아직 정해지지 않았다. 코드에 숫자를 넣지 말고 먼저 질문한다."

??? failure "답이 여전히 영어로 나옵니다"
    지침 파일이 적용되지 않은 경우입니다. 위의 References 항목을 차례로 확인합니다.
