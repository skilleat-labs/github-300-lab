# 실습 3-3. 스킬로 아이디어 검토하기

!!! abstract "이 실습에서 할 일"
    - 업무 아이디어를 검토하는 요청을 **스킬** `.github/skills/idea/SKILL.md`로 저장합니다.
    - 지금 쓰는 **Copilot** 하네스 채팅에서 `/idea`로 실행해, 총무팀의 월간 집계 업무를 자동화할 아이디어를 검토합니다.
    - `/idea` 없이 부탁해도 스킬이 쓰이는지 보고, 내 업무로도 실행한 뒤 커밋해 팀이 함께 쓸 수 있게 합니다.

    **예상 시간** 약 11분

## 스킬이란

| 구분 | 지침 파일 (3-2) | 스킬 (3-3) |
|---|---|---|
| 파일 | `.github/copilot-instructions.md` | `.github/skills/이름/SKILL.md` |
| 언제 쓰이나 | 모든 채팅에 **항상** 자동으로 | `/이름`으로 **부를 때**, 또는 요청이 **설명과 맞을 때** 자동으로 |
| 무엇을 쓰나 | 늘 지켜야 할 규칙 | 반복하는 작업 하나의 순서와 형식 |

좋은 검토 요청을 스킬로 저장해 두면 `/idea` 한 번으로 같은 형식의 결과를 받고, 팀과 나눠 쓸 수 있습니다.

### 한 번 만들면 여러 곳에서 씁니다

스킬은 GitHub만의 기능이 아니라 **Agent Skills라는 개방형 표준**입니다. "`SKILL.md`가 든 폴더 하나"라는 같은 형식을 여러 AI 도구가 읽습니다.

| 어디서 | 스킬을 두는 곳 (리포지토리, 내 컴퓨터) |
|---|---|
| **GitHub Copilot**: VS Code, Visual Studio, JetBrains, Copilot CLI, github.com의 클라우드 에이전트와 코드 리뷰 | `.github/skills/`, `~/.copilot/skills/` |
| Claude | `.claude/skills/`, `~/.claude/skills/` |
| OpenAI Codex | `.agents/skills/`, `~/.agents/skills/` |

- 오늘은 **`.github/skills/`**에 만듭니다. 리포지토리에 커밋하면 VS Code뿐 아니라 github.com에서 일하는 Copilot 클라우드 에이전트(5-3)와 코드 리뷰(6-1)도 이 스킬을 쓸 수 있습니다.
- GitHub 문서는 리포지토리의 `.claude/skills/`, `.agents/skills/`도 Copilot이 읽는 스킬 위치로 안내합니다. 다른 도구용으로 만든 스킬도 리포지토리에 있으면 Copilot이 씁니다.
- 읽는 위치와 쓸 수 있는 머리말은 도구마다 조금 다릅니다. 다른 도구에서 쓸 때는 그 도구의 문서를 확인합니다.
- 스킬 폴더에는 `SKILL.md` 말고도 예시, 스크립트, 참고 자료를 함께 넣을 수 있습니다. 오늘은 `SKILL.md` 하나만 씁니다.

!!! warning "남이 만든 스킬은 열어 보고 씁니다"
    GitHub CLI의 `gh skill install`로 공개된 스킬을 받아 올 수 있습니다. GitHub는 스킬을 검증하지 않으며, 숨은 지시나 악성 스크립트가 들어 있을 수 있습니다. 받기 전에 `gh skill preview`로 내용을 먼저 봅니다. (오늘 PC에는 GitHub CLI를 설치하지 않으므로 소개만 합니다.)

## STEP 1. skills 폴더와 파일 만들기

1. 왼쪽 탐색기에서 `.github` 폴더를 마우스 오른쪽 버튼으로 클릭하고 **New File...**을 고릅니다.
2. 아래를 그대로 입력하고 Enter를 누릅니다. `/`를 넣으면 폴더 두 개와 파일이 한 번에 만들어집니다.

    ```text
    skills/idea/SKILL.md
    ```

확인: 탐색기에 `.github/skills/idea/SKILL.md`가 보입니다. 폴더 이름은 소문자 `idea`, 파일 이름은 대문자 `SKILL.md`입니다.

!!! tip "메뉴로 만드는 방법"
    명령 팔레트(Windows `Ctrl+Shift+P`, Mac `⇧⌘P`)에서 **Chat: Open Customizations** → **Skills** → **Workspace** 옆 **New Skill**로 만들어도 됩니다.

## STEP 2. 스킬 내용 쓰기

1. 아래 내용을 통째로 복사해 `SKILL.md`에 붙여 넣습니다.

    ```markdown
    ---
    name: idea
    description: 업무 설명을 읽고 자동화 아이디어 3개를 비교하고 무엇부터 만들지 정한다. 업무 자동화 아이디어 검토를 부탁받으면 쓴다.
    ---
    사용자가 준 업무 설명(첨부한 파일 또는 입력한 글)을 읽고 자동화 아이디어를 검토한다.

    ## 형식
    ### 아이디어 3개
    표로 쓴다. 열은 아이디어, 줄어드는 일, 만드는 난이도(상, 중, 하), 위험이다.

    ### 먼저 만들 것
    - 한 개를 고르고 이유를 쓴다.
    - 가장 작은 첫 버전의 입력, 처리, 출력을 한 줄씩 쓴다.
    - 결과가 맞는지 사람이 확인할 방법을 쓴다.

    ### 확인 필요
    업무 설명에 없어서 정하지 못한 것을 적는다. 없으면 "없음".

    ## 규칙
    - 업무 설명에 없는 숫자나 효과를 지어내지 않는다.
    - 개인정보, 회사 자료를 다루면 위험에 적는다.
    - 파일은 만들거나 고치지 않는다. 검토만 한다.
    - 한국어로 쓴다.
    ```

2. 저장합니다(Windows `Ctrl+S`, Mac `⌘S`).

확인: 파일 맨 위가 `---`로 시작하고, `name: idea`와 `description` 두 줄 뒤에 다시 `---`가 있습니다.

!!! note "각 부분의 뜻"
    - 맨 위 `---` 사이를 **머리말**이라고 합니다.
    - `name`은 명령 이름입니다(`/idea`). **소문자, 숫자, 하이픈만** 쓰고 **폴더 이름과 같아야** 합니다. 다르면 오류 없이 스킬이 조용히 안 읽힙니다.
    - `description`은 **무엇을 하는지와 언제 쓰는지**입니다. Copilot은 이 설명을 보고 요청과 맞으면 스킬을 스스로 불러옵니다. 그래서 구체적으로 씁니다.
    - 아래 본문이 Copilot이 따를 순서와 형식입니다. 3교시에 배운 목표, 형식, 제약이 그대로 들어 있습니다.

## STEP 3. /idea로 실행하기

1. Chat 보기에서 **+**(**New Chat**)를 클릭합니다. Session Target **Copilot**, 역할 **Ask**, 모델 **Copilot Fusion**.
2. 입력 칸에 `/`를 입력하고, 목록에서 **idea**를 고릅니다.
3. 이어서 한 칸 띄우고 `#04`를 입력해 목록에서 `04_월간집계_업무.md`를 고릅니다. 입력 칸이 아래처럼 됩니다.

    ```text
    /idea #04_월간집계_업무.md
    ```

4. Enter를 누릅니다.

확인: 아이디어 3개와 먼저 만들 것이 나옵니다. "부서별 노쇼 순위를 전사에 공유해도 되는가"가 **확인 필요**에 들어가 있으면 잘 된 것입니다. 정해 버렸거나 문서에 없는 절감 시간을 지어냈다면 사람이 지웁니다.

## STEP 4. /idea 없이 부탁해 보기

스킬은 부르지 않아도 요청이 `description`과 맞으면 Copilot이 스스로 불러옵니다.

1. **+**(**New Chat**)로 새 채팅을 엽니다. 역할 **Ask**.
2. 아래를 붙여 넣고, `#04_월간집계_업무.md`를 붙인 뒤 Enter를 누릅니다.

    ```text
    이 업무를 자동화할 아이디어를 검토해 주세요.
    ```

확인: STEP 3과 같은 형식(아이디어 3개, 먼저 만들 것, 확인 필요)으로 답하면 스킬이 쓰인 것입니다. 답변의 **References**나 작업 기록을 펼쳐 `SKILL.md`가 보이는지도 확인합니다.

!!! tip "형식이 다르게 나오면"
    자동으로 불러올지는 Copilot이 판단합니다. 안 쓰였다면 `description`이 요청과 덜 맞는 것입니다. 꼭 이 형식이 필요할 때는 `/idea`로 직접 부릅니다.

## STEP 5. 내 업무로 한 번 더

1. 내 업무에서 반복하는 일을 두세 문장으로 생각합니다. 회사 이름, 고객 정보, 실제 수치는 쓰지 않습니다.
2. 새 채팅(역할 **Ask**)에 `/idea`를 고르고, 한 칸 띄운 뒤 그 문장을 이어서 씁니다.

    ```text
    /idea 매주 월요일 부서별 진행 현황을 엑셀 세 개에서 모아 표 하나로 만들어 팀장에게 보낸다. 한 시간쯤 걸린다.
    ```

3. Enter를 누르고 결과를 읽습니다.

확인: 내 업무에 대한 "먼저 만들 것"과 "확인 필요"를 받았습니다. 이 결과는 7-2에서 다시 씁니다. 필요하면 메모해 둡니다.

## STEP 6. 커밋하기

1. 소스 제어(Windows `Ctrl+Shift+G`, Mac `⌃⇧G`)를 엽니다.
2. **Changes**에 `SKILL.md`만 있는지 확인합니다.
3. 메시지 칸에 아래를 입력하고 **Commit**, 이어서 **Sync Changes**를 누릅니다.

    ```text
    아이디어 검토 스킬 추가
    ```

확인: github.com의 `room-practice`에서 `.github/skills/idea/SKILL.md`가 보입니다.

!!! tip "팀에서 재사용하기"
    스킬을 리포지토리에 커밋하면 이 리포지토리를 가져간 **팀원 모두**가 같은 `/idea`를 씁니다. 나만 쓰는 스킬은 내 컴퓨터의 `~/.copilot/skills/`에 둡니다.

## 다 됐는지 확인

- [ ] `.github/skills/idea/SKILL.md`에 머리말(`name: idea`, `description`)이 있고, 폴더 이름과 `name`이 같습니다.
- [ ] Copilot 하네스 채팅에서 `/idea #04_월간집계_업무.md`로 실행했습니다.
- [ ] `/idea` 없이 부탁했을 때 스킬이 쓰이는지 확인했습니다.
- [ ] 결과에서 문서에 없는 내용을 지어내지 않았는지 확인했습니다.
- [ ] 내 업무 문장으로도 실행해 봤습니다.
- [ ] 스킬을 커밋하고 GitHub에 올렸습니다.

## 막히면

!!! tip "먼저 Copilot과 함께 해결합니다"
    오류 메시지나 막힌 상황을 Chat(Ask)에 붙여 넣고 원인과 해결 순서를 묻습니다. 아래는 자주 막히는 경우입니다. 묻는 방법은 [막혔을 때](../setup/3-troubleshooting.md#copilot)에 있습니다.

??? failure "/를 입력해도 idea가 목록에 없습니다"
    1. 위치가 정확히 `.github/skills/idea/SKILL.md`인지 봅니다. 파일 이름은 대문자 `SKILL.md`입니다.
    2. `name: idea`가 폴더 이름 `idea`와 같은지 봅니다. 대문자, 공백, 점이 들어가면 조용히 안 읽힙니다.
    3. 파일을 저장했는지 확인하고 **+**로 새 채팅을 엽니다.

??? failure "머리말이 글자로 그대로 보이거나 설명이 목록에 안 나옵니다"
    파일 첫 줄이 정확히 `---`인지 봅니다. 앞에 빈 줄이나 공백이 있으면 머리말로 인식되지 않습니다.

??? failure "파일 내용과 상관없는 답을 합니다"
    `#04_월간집계_업무.md`가 입력 칸에 파일로 붙었는지 봅니다. 글자로만 남아 있으면 `#04`를 지우고 다시 입력해 목록에서 고릅니다. **+**(**Add Context**)로 파일을 붙여도 됩니다.

??? failure "Ask인데 파일을 만들겠다고 합니다"
    역할이 **Agent**로 되어 있지 않은지 봅니다. 스킬 본문의 "파일은 만들거나 고치지 않는다" 줄이 빠지지 않았는지도 확인합니다.
