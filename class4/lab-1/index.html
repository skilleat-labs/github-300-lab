    실습 4-1. 브랜치와 계획¶

    이 실습에서 할 일

    • 개인 리포지토리 room-practice에 브랜치 overlap-check를 만듭니다.
    • Copilot에게 /plan으로 "현업 요청 1번, 겹치는 예약 막기"의 구현 계획을 받습니다.
    • 계획을 검토 기준으로 읽고, 빠진 것을 고쳐 달라고 다시 요청합니다. 코드는 아직 바꾸지 않습니다.

    소요 시간 약 6분 실습 장소 개인 리포지토리 room-practice (VS Code) 관련 교안 4교시 교안

    준비¶

    • VS Code에서 문서/copilot-lab/room-practice 폴더가 열려 있어야 합니다.

    • 2-3에서 고친 18시 버그가 main에 커밋되어 있어야 합니다. 터미널에서 테스트를 한 번 돌려 봅니다.

      python -m pytest

      python3 -m pytest

    • 소스 제어에 커밋하지 않은 변경이 남아 있으면 먼저 정리합니다. data/reservations.json 변경은 Discard Changes(변경 취소)로 되돌립니다.

    이번 교시에 하는 일 한눈에 보기

    4-1 계획 → 4-2 구현과 테스트 → 4-3 PR과 CI. 오늘 오후 팀 실습에서 이 흐름을 그대로 다시 씁니다. 그래서 지금 하나하나 천천히 익혀 둡니다.

    STEP 1. 브랜치 overlap-check 만들기¶

    main에서 바로 고치지 않고, 이번 기능만을 위한 작업 공간(브랜치)을 따로 만듭니다.

    1. VS Code 아래쪽 파란 상태 표시줄 왼쪽에서 지금 브랜치 이름 main을 클릭합니다.
    2. 화면 위쪽에 목록이 열립니다. Create new branch...(새 브랜치 만들기)를 클릭합니다.

    3. 브랜치 이름을 입력하고 Enter를 누릅니다.

      overlap-check

    4. 상태 표시줄의 브랜치 이름이 overlap-check로 바뀌었는지 봅니다.

    확인: 상태 표시줄 왼쪽에 overlap-check가 보입니다.

    브랜치는 아직 내 PC에만 있어요

    지금 만든 브랜치는 GitHub에 올라가지 않았습니다. 4-3에서 Publish Branch로 올립니다.

    STEP 2. 새 채팅을 Copilot 하네스로 열기¶

    1. Chat 보기를 엽니다. Windows는 Ctrl+Alt+I, Mac은 Ctrl+Cmd+I
    2. Chat 보기 위쪽 +(New Chat, 새 채팅)를 클릭합니다. 앞 실습의 대화가 섞이지 않게 하려는 것입니다.
    3. 입력 칸 아래 Session Target(세션 대상)이 Copilot인지 봅니다. 아니면 눌러서 Copilot을 고릅니다.
    4. 모델이 Auto, 권한이 Manual인지 봅니다.

    확인: 새 채팅이 비어 있고, Session Target이 Copilot입니다.

    왜 새 채팅인가요?

    프롬프트 전략 "Keep history relevant"(대화 기록을 관련 있게)입니다. 앞 실습의 18시 버그 이야기가 남아 있으면 Copilot이 엉뚱한 곳을 고치려 할 수 있습니다.

    STEP 3. /plan으로 계획 요청하기¶

    /plan은 Copilot 하네스에서 Plan(계획) 역할로 일하게 하는 명령입니다. 코드를 조사한 뒤 구현 계획만 세우고, 파일은 바꾸지 않습니다.

    1. 입력 칸 왼쪽 +(Add Context, 맥락 추가) → Files & Folders를 클릭합니다.
    2. booking/rules.py를 고릅니다.
    3. 같은 방법으로 docs/00_현업요청.md, docs/01_킥오프_회의록.md, tests/test_rules.py를 추가합니다. 탐색기에서 파일을 입력 칸으로 끌어다 놓아도 됩니다.

    4. Chat에 붙여 넣기

      /plan 현업 요청 1번 "겹치는 예약 막기"를 구현하는 계획을 세워 주세요.

배경: booking/rules.py의 validate()에 "# TODO: 같은 회의실, 같은 날짜에 시간이 겹치는 예약은 막아야 한다 (현업 요청 1번)"이 있습니다.
근거 문서: docs/00_현업요청.md, docs/01_킥오프_회의록.md (결정한 것 1번)

계획에 넣어 주세요.
1. 어떤 파일의 어디를 바꾸는지
2. "겹친다"의 정확한 판단 기준
3. 실패할 때 보여 줄 오류 메시지 (예: "이미 예약된 시간입니다")
4. tests/test_rules.py에 추가할 테스트 목록
5. 문서에 없어서 확인이 필요한 것

아직 코드는 바꾸지 마세요.

    5. Enter를 누르고 답을 기다립니다. Copilot이 파일을 읽는 동안 "읽는 중" 표시가 지나갑니다.

    확인: 바꿀 파일, 판단 기준, 테스트 목록이 들어간 계획이 채팅에 보입니다. 파일은 하나도 바뀌지 않았습니다.

    도구 사용 승인이 뜨면

    /plan은 주로 읽기만 합니다. 그래도 권한이 Manual이라 승인을 묻는 창이 뜰 수 있습니다. 무엇을 하려는지 읽고, 파일을 읽거나 검색하는 것이면 승인합니다. 파일을 고치려는 것이면 승인하지 않습니다.

    STEP 4. 계획 검토하기¶

    Copilot의 계획은 매번 조금씩 다릅니다. 문장이 달라도 괜찮습니다. 아래 기준을 하나씩 대 보며 읽습니다.

    검토 기준 계획에 이런 내용이 있으면 됩니다
    바꿀 곳 booking/rules.py의 validate(), TODO 자리
    같은 회의실, 같은 날짜만 회의실(room_id)과 날짜(date)가 같은 예약끼리만 비교
    겹침 판단 새 시작이 기존 끝보다 이르고, 기존 시작이 새 끝보다 이르면 겹침
    맞닿은 시간 10:00~11:00이 있을 때 11:00~12:00은 겹침이 아님 (11:00 끝, 11:00 시작)
    다른 회의실, 다른 날짜 같은 시간이라도 허용
    자기 자신 제외 비교할 때 같은 id(자기 자신)는 빼기
    테스트 겹치면 실패, 맞닿으면 성공, 다른 회의실이면 성공 같은 경우가 들어 있음
    범위 밖 최대 예약 시간, 노쇼 자동 취소, 정원 검사는 이번에 하지 않음

    메모장에 빠진 기준을 적어 둡니다.

    확인: 위 표에서 계획에 빠졌거나 틀린 항목을 하나 이상 찾았거나, 모두 들어 있다는 것을 확인했습니다.

    왜 계획부터 보나요?

    코드가 수백 줄 나온 뒤에 "맞닿은 시간은 겹침이 아닌데요"라고 고치는 것보다, 계획 단계에서 한 줄 고치는 것이 훨씬 빠릅니다. 계획은 PM, BA가 읽고 판단할 수 있는 말로 쓰여 있으니, 오늘 오후 역할극에서도 이 검토를 그대로 합니다.

    STEP 5. 계획 고쳐 달라고 요청하기¶

    검토에서 찾은 것을 그대로 말합니다. 아래는 예시입니다. 내 계획에 이미 있는 항목은 지우고 붙여 넣습니다.

    Chat에 붙여 넣기

    계획을 아래대로 고쳐 주세요.
- 끝과 시작이 맞닿으면(예: 10:00~11:00과 11:00~12:00) 겹침이 아닙니다. 테스트에 넣어 주세요.
- 다른 회의실이나 다른 날짜는 같은 시간이어도 예약할 수 있어야 합니다. 테스트에 넣어 주세요.
- 비교할 때 같은 id의 예약(자기 자신)은 빼 주세요.
- 오류 메시지는 "이미 예약된 시간입니다"로 시작하고, 겹치는 예약 번호와 시간을 함께 보여 주세요.
- 최대 예약 시간과 정원 검사는 이번 범위가 아니니 빼 주세요.
아직 코드는 바꾸지 마세요.

    확인: 고친 계획에 맞닿은 시간, 다른 회의실과 다른 날짜, 자기 자신 제외가 모두 보입니다.

    확인이 필요한 것이 나오면

    Copilot이 "같은 시간에 같은 사람이 두 회의실을 잡아도 되나요?"처럼 문서에 없는 질문을 할 수 있습니다. 좋은 신호입니다. 문서에 없는 정책은 Copilot이 정하지 않게 합니다. 이번 실습에서는 "이번 범위가 아닙니다"라고 답하면 됩니다.

    채팅은 닫지 않습니다. 4-2에서 이 대화에 이어서 구현을 요청합니다.

    다 됐는지 확인¶

    • 상태 표시줄 브랜치 이름이 overlap-check다
    • 새 채팅의 Session Target이 Copilot이다
    • /plan으로 받은 계획에 바꿀 파일, 겹침 기준, 테스트 목록이 있다
    • 맞닿은 시간, 다른 회의실과 다른 날짜, 자기 자신 제외를 검토하고 빠진 것을 고쳐 달라고 했다
    • 아직 파일은 하나도 바뀌지 않았다 (소스 제어에 변경 0)

    막히면¶

    먼저 Copilot과 함께 해결합니다

    오류 메시지나 막힌 상황을 Chat(Ask)에 붙여 넣고 원인과 해결 순서를 묻습니다. 아래는 자주 막히는 경우입니다. 묻는 방법은 막혔을 때에 있습니다.

    상태 표시줄에 브랜치 이름이 안 보여요

    VS Code가 Git 리포지토리 폴더가 아닌 곳을 열고 있을 수 있습니다. File → Open Folder로 문서/copilot-lab/room-practice를 다시 엽니다. 폴더 안에 .git 폴더가 있어야 브랜치가 보입니다.

    Create new branch를 눌렀는데 커밋하지 않은 변경이 있다고 해요

    브랜치를 만들어도 변경은 그대로 따라옵니다. 대부분 data/reservations.json 변경입니다. 소스 제어에서 그 파일 오른쪽 되돌리기 아이콘(Discard Changes)을 누르고 다시 만듭니다.

    /plan을 쳤는데 계획 대신 코드를 바로 고쳐요

    Session Target이 Copilot이 아닐 수 있습니다. +(New Chat)로 새 채팅을 열고 Session Target을 Copilot으로 고른 뒤 다시 보냅니다. 이미 파일이 바뀌었다면 요청 위에 마우스를 올리고 Restore Checkpoint를 눌러 되돌립니다.

    계획이 너무 길고 어려워요

    Chat에 "PM이 읽을 수 있게 5줄로 요약해 주세요. 바꿀 파일, 겹침 기준, 테스트 목록만"이라고 다시 요청합니다. 그래도 어려우면 위 STEP 4 표만 대 보며 "있다/없다"만 체크합니다.

    계획에 정원 검사나 최대 2시간 같은 것도 들어 있어요

    회의록의 "결정하지 못한 것"을 Copilot이 결정해 버린 경우입니다. STEP 5 예시처럼 "이번 범위가 아니니 빼 주세요"라고 요청합니다. 문서에 없는 정책을 Copilot이 지어내는 것을 막는 것도 검토입니다.
