    프롬프트 모음¶

    오늘 과정에서 쓴 프롬프트를 교시별로 모았습니다. 오른쪽 위 복사 버튼으로 복사합니다. 어떤 하네스와 역할에서 보내는지, 무엇을 첨부하는지는 각 실습 페이지를 함께 봅니다.

    그대로 쓰지 말고 바꿔 쓰세요

    #3, S1, (여기에 ...) 같은 부분은 내 상황에 맞게 바꿉니다. Copilot 답은 매번 달라지니, 각 실습 페이지의 "확인:" 기준으로 결과를 검토합니다.

    1교시 시작하기¶

    1-1 첫 인사 (Copilot 하네스) 실습 1-1

    안녕하세요. 지금 어떤 역할(Ask, Agent)로 대화하고 있는지와, 이 역할로 할 수 있는 일을 두 줄로 알려 주세요.

    1-3 맥락 없이 묻기 실습 1-3

    이 프로젝트가 무엇을 하는지 개발을 모르는 기획자에게 설명해 주세요. 5줄 이내로, 전문 용어 없이 써 주세요.

    1-3 #codebase를 붙여 다시 묻기 (앞에 #codebase를 먼저 넣습니다)

    이 프로젝트가 무엇을 하는지 개발을 모르는 기획자에게 설명해 주세요. 5줄 이내로, 전문 용어 없이 써 주세요. 할 수 있는 일(명령)도 같이 알려 주세요.

    1-3 현업 요청 문서를 첨부해 묻기 (docs/00_현업요청.md 첨부)

    첨부한 현업 요청의 "바라는 점" 5가지 중에서 지금 코드에 이미 구현된 것과 아직 안 된 것을 표로 나눠 주세요. 각 항목마다 근거가 되는 파일 이름을 적어 주세요.

    2교시 기본기¶

    2-2 /explain (booking/report.py의 함수 선택) 실습 2-2

    /explain 선택한 코드가 무엇을 계산하는지 기획자가 이해할 수 있게 설명해 주세요. 이용률 "높음, 보통, 낮음, 없음"을 나누는 기준을 시간 숫자로 정확히 적어 주세요.

    2-2 인라인 채팅 (편집기에서 Windows Ctrl+I, Mac Cmd+I)

    lv가 뭐야? 어떤 값이 들어가고 어디에 쓰여? 코드는 고치지 말고 설명만 해 줘.

    2-3 18시 버그 고치기 (Agent, docs/02_현행_업무.md 첨부) 실습 2-3

    아래 명령으로 17:00~18:00 예약을 넣으면 실패합니다.
python -m booking add --room R2 --title 마감회의 --date 2026-11-10 --start 17:00 --end 18:00 --booker 홍길동 --attendees 2
결과:
[예약 실패]
 - 운영 시간(09:00~18:00) 밖입니다.

첨부한 현행 업무 문서의 운영 규칙에는 "18:00에 끝나는 예약은 가능"이라고 되어 있습니다.
booking/rules.py만 고쳐서 18:00에 끝나는 예약은 되고, 18:00을 넘겨 끝나는 예약(예: 17:30~18:30)은 계속 막히게 해 주세요.
다른 파일과 data 폴더는 바꾸지 마세요.

    3교시 프롬프트와 맥락¶

    3-1 zero-shot (docs/01_킥오프_회의록.md 첨부) 실습 3-1

    첨부한 회의록을 사용자 스토리로 정리해 주세요.

    3-1 few-shot

    첨부한 회의록의 "결정한 것"을 사용자 스토리로 정리해 주세요. 아래 예시와 같은 형식으로 써 주세요.

### S1. 겹치는 예약 막기
- 스토리: 예약하는 직원으로서, 같은 회의실 같은 시간에 이미 예약이 있으면 예약이 안 되기를 원한다. 회의실 앞에서 다투지 않기 위해서다.
- 인수 조건:
  - 10:00~11:00 예약이 있으면 10:30~11:30 예약은 "이미 예약된 시간"으로 실패한다.
  - 11:00~12:00 예약은 성공한다(끝과 시작이 맞닿는 것은 겹침이 아니다).

    3-1 규칙을 넣어 다시 요청

    다시 정리해 주세요. 규칙:
1. 회의록의 "결정한 것" 4개만 사용자 스토리로 만든다.
2. 회의록에 없는 정책은 정하지 말고 "확인 필요"로 표시한다.
3. "결정하지 못한 것"은 스토리로 만들지 말고, 맨 아래 "확인 필요" 목록에 누가 정해야 하는지와 함께 적는다.
4. "이번 범위가 아닌 것"은 넣지 않는다.

    3-1 파일로 저장 (Agent)

    바로 앞의 마지막 답(사용자 스토리 4개와 확인 필요 목록)을 docs/03_사용자스토리.md 파일로 저장해 주세요. 맨 위 제목은 "# 회의실 예약 서비스 사용자 스토리"로 해 주세요. 다른 파일은 바꾸지 마세요.

    3-2 지침 파일 전후 비교 질문 실습 3-2

    한 번에 너무 오래 예약하지 못하게 최대 예약 시간 검사를 booking/rules.py에 넣으려고 합니다. 어떻게 바꾸면 되는지 알려 주세요.

    3-3 스킬 /idea (Copilot 하네스, Ask, #04_월간집계_업무.md 첨부) 실습 3-3

    /idea #04_월간집계_업무.md

    이 업무를 자동화할 아이디어를 검토해 주세요.

    지침 파일과 스킬의 전체 내용은 실습 3-2, 실습 3-3에 있습니다.

    4-1 계획 고치기

    계획을 아래대로 고쳐 주세요.
- 끝과 시작이 맞닿으면(예: 10:00~11:00과 11:00~12:00) 겹침이 아닙니다. 테스트에 넣어 주세요.
- 다른 회의실이나 다른 날짜는 같은 시간이어도 예약할 수 있어야 합니다. 테스트에 넣어 주세요.
- 비교할 때 같은 id의 예약(자기 자신)은 빼 주세요.
- 오류 메시지는 "이미 예약된 시간입니다"로 시작하고, 겹치는 예약 번호와 시간을 함께 보여 주세요.
- 최대 예약 시간과 정원 검사는 이번 범위가 아니니 빼 주세요.
아직 코드는 바꾸지 마세요.

    4-2 구현 (Agent) 실습 4-2

    위에서 고친 계획대로 구현해 주세요.

- tests/test_rules.py에 계획의 테스트를 추가해 주세요. 기존 테스트 4개는 그대로 두세요.
- 다 되면 python -m pytest를 실행해서 결과를 보여 주세요.
- 계획에 없는 파일은 바꾸지 마세요.

    4-2 경계값 테스트 더 받기

    /tests booking/rules.py의 겹침 검사에 대한 경계값 테스트를 tests/test_rules.py에 더 추가해 주세요.

- 기존 예약을 완전히 감싸는 예약(09:30~11:30)은 실패
