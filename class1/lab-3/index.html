    실습 1-3. Copilot에게 첫 질문¶

    이 실습에서 할 일

    • Ask 역할로 프로젝트 설명을 듣고, #codebase를 붙였을 때 답이 어떻게 달라지는지 비교합니다.
    • 현업 요청 문서를 첨부해 "이미 된 것과 안 된 것"을 묻고, 사람이 코드로 검증합니다.
    • 인라인 제안(회색 글씨)을 한 번 받아 보고, 원래대로 되돌립니다.

    예상 시간 약 6분

    준비¶

    • 실습 1-2에서 room-practice를 VS Code로 열어 두었어야 합니다.
    • Chat 보기를 엽니다(Windows Ctrl+Alt+I, Mac ⌃⌘I). Session Target Copilot, 역할 Ask, 모델 Copilot Fusion인지 확인합니다.

    STEP 1. 맥락 없이 물어보기¶

    1. Chat 위쪽의 +(New Chat)를 눌러 새 채팅을 엽니다.
    2. 역할이 Ask인지 확인합니다.

    3. Chat에 붙여 넣고 Enter를 누릅니다.

      이 프로젝트가 무엇을 하는지 개발을 모르는 기획자에게 설명해 주세요. 5줄 이내로, 전문 용어 없이 써 주세요.

    4. 답을 읽고, 아래 질문에 스스로 답해 봅니다. 답이 프로젝트 파일 내용을 실제로 읽고 쓴 것인가요, 아니면 일반적인 설명인가요?

    확인: 답이 돌아왔습니다. 회의실 예약 이야기가 나올 수도 있고, 지금 열려 있는 파일 위주의 설명만 나올 수도 있습니다.

    STEP 2. #codebase를 붙여 다시 물어보기¶

    #codebase는 "리포지토리 전체에서 관련 내용을 찾아서 답해 달라"는 맥락 표시입니다.

    1. 새 채팅(+)을 엽니다.
    2. 입력 칸에 #를 입력하면 맥락 항목 목록이 뜹니다. codebase를 고릅니다.

    3. 이어서 아래 내용을 붙여 넣고 Enter를 누릅니다.

      이 프로젝트가 무엇을 하는지 개발을 모르는 기획자에게 설명해 주세요. 5줄 이내로, 전문 용어 없이 써 주세요. 할 수 있는 일(명령)도 같이 알려 주세요.

    4. STEP 1의 답과 비교합니다.

    확인: 이런 내용이 들어 있으면 됩니다. 회의실 예약 서비스, 예약 목록 보기와 예약하기, 회의실 목록, 이용률 보고서, 현황판 웹페이지. 응답의 References(참조)를 펼쳐 어떤 파일을 읽었는지도 봅니다.

    리포지토리 전체를 보게 하려면 #codebase

    예전 자료에 나오는 @참여자(@로 시작하는 이름)는 더 이상 쓰지 않습니다. 리포지토리 전체에서 찾아 답하게 하려면 #codebase를 붙입니다.

    STEP 3. 현업 요청 문서를 첨부해 묻기¶

    1. 새 채팅(+)을 엽니다.
    2. 왼쪽 탐색기에서 docs/00_현업요청.md를 마우스로 끌어 Chat 입력 칸에 놓습니다. 입력 칸 위에 파일 이름이 붙으면 첨부된 것입니다.
    3. 입력 칸에 #를 입력하고 codebase도 고릅니다.

    4. Chat에 붙여 넣고 Enter를 누릅니다.

      첨부한 현업 요청의 "바라는 점" 5가지 중에서 지금 코드에 이미 구현된 것과 아직 안 된 것을 표로 나눠 주세요. 각 항목마다 근거가 되는 파일 이름을 적어 주세요.

    확인: 표가 나옵니다. 대체로 "겹치는 예약 막기, 정원 초과 막기, 예약 취소는 아직 안 됨" 쪽으로 나오면 됩니다. 현황판은 build_site.py가 있어서 "구현됨"이나 "일부 있음"으로 나옵니다. 노쇼 줄이기는 회의록에서 결정하지 못한 일이라 "안 됨"이 맞습니다.

    파일을 첨부하는 다른 방법

    입력 칸의 +(Add Context) 버튼을 누르고 Files & Folders에서 파일을 골라도 됩니다.

    STEP 4. 사람이 검증하기¶

    Copilot의 답은 틀릴 수 있습니다. 표에 "안 됨"이라고 나온 항목 하나를 직접 확인합니다.

    1. 탐색기에서 booking/rules.py를 엽니다.
    2. validate 함수 안에서 어떤 검사를 하는지 주석과 오류 메시지를 읽습니다.
      • 없는 회의실
      • 끝나는 시간이 시작 시간보다 빠름
      • 운영 시간(09:00~18:00) 밖
      • 30분 단위가 아님
    3. 맨 아래 # TODO: 같은 회의실, 같은 날짜에 시간이 겹치는 예약은 막아야 한다 (현업 요청 1번) 줄을 찾습니다.
    4. 정원(capacity)을 검사하는 줄이 있는지 찾아봅니다.

    확인: 겹침 검사는 TODO로만 남아 있고, 정원 검사는 없습니다. Copilot 표와 같으면 맞게 답한 것이고, 다르면 Copilot이 틀린 것입니다. 틀린 부분을 찾았다면 같은 채팅에 "이 부분은 코드와 다릅니다. 근거 파일을 다시 확인해 주세요"라고 알려 고치게 합니다. 좋은 검증 사례입니다.

    검증은 사람의 몫

    오늘 과정의 원칙은 "Copilot이 쓰고, 사람이 검토하고 검증한다"입니다. 그럴듯한 답일수록 근거 파일을 열어 한 번 더 봅니다.

    STEP 5. 인라인 제안 맛보기¶

    인라인 제안은 편집기에서 글을 쓰면 Copilot이 다음 내용을 회색 글씨로 미리 보여 주는 기능입니다. 크레딧을 쓰지 않습니다.

    1. booking/rules.py를 열어 둔 상태에서 파일 맨 아래 빈 줄을 클릭합니다.

    2. Enter를 두 번 눌러 빈 줄을 만들고 아래 주석을 입력합니다.

      # 예약 시간을 분 단위로 돌려주는 함수

    3. 주석 끝에서 Enter를 누르고 1~2초 기다립니다.

    4. 회색 글씨로 함수 제안이 나타납니다.
    5. Tab을 눌러 제안을 받아들입니다.
    6. 다음 줄에서 회색 제안이 또 나오면, 이번에는 Esc를 눌러 거절해 봅니다.

    확인: Tab을 누르면 회색 글씨가 진짜 코드로 바뀌고, Esc를 누르면 회색 글씨가 사라집니다.

    제안이 안 나오면

    주석 아래에서 def까지 직접 입력하고 잠시 기다려 봅니다. 그래도 안 나오면 상태 표시줄의 Copilot 아이콘에 경고 표시가 있는지 봅니다.

    STEP 6. 원래대로 되돌리기¶

    이번 실습은 맛보기라서 rules.py 변경을 남기지 않습니다. 커밋하지 않습니다.

    1. rules.py 편집기 안을 클릭합니다.
    2. Windows는 Ctrl+Z, Mac은 ⌘Z를 여러 번 눌러 추가한 주석과 함수가 모두 사라질 때까지 되돌립니다.
    3. Windows는 Ctrl+S, Mac은 ⌘S로 저장합니다.
    4. 왼쪽 활동 막대의 소스 제어 아이콘(가지 모양)을 클릭합니다. 단축키는 Windows Ctrl+Shift+G, Mac ⌃⇧G입니다.

    확인: 소스 제어의 Changes 목록에 rules.py가 없습니다. 있으면 rules.py에 마우스를 올리고 Discard Changes(굽은 화살표)를 눌러 되돌립니다.

    다 됐는지 확인¶

    • #codebase 없이 물은 답과 붙여서 물은 답의 차이를 봤습니다.
    • docs/00_현업요청.md를 끌어다 놓아 첨부하는 방법을 해 봤습니다.
    • rules.py의 TODO 주석으로 Copilot의 표를 직접 검증했습니다.
    • 인라인 제안을 Tab으로 받고 Esc로 거절해 봤습니다.
    • 소스 제어 Changes 목록이 비어 있습니다.

    막히면¶

    먼저 Copilot과 함께 해결합니다

    오류 메시지나 막힌 상황을 Chat(Ask)에 붙여 넣고 원인과 해결 순서를 묻습니다. 아래는 자주 막히는 경우입니다. 묻는 방법은 막혔을 때에 있습니다.

    #를 입력해도 codebase가 목록에 없습니다

    # 다음에 codebase를 이어서 입력해 목록을 좁혀 봅니다. 그래도 없으면 Session Target이 Copilot인지 확인하고 새 채팅을 엽니다.

    파일을 끌어다 놓았는데 첨부되지 않습니다

    탐색기의 파일 이름을 Chat 입력 칸 위에 정확히 놓아야 합니다. 어렵다면 입력 칸의 +(Add Context) → Files & Folders에서 00_현업요청.md를 고릅니다.

    Copilot이 파일을 고치겠다고 합니다

    역할이 Agent로 되어 있는 경우입니다. 이 실습은 Ask 역할로 합니다. 새 채팅을 열고 역할 선택기에서 Ask를 고른 뒤 다시 묻습니다.

    답이 영어로 나옵니다

    프롬프트 끝에 "한국어로 답해 주세요."를 붙여 다시 묻습니다. 3교시에 지침 파일로 이것을 자동으로 맞추는 방법을 배웁니다.

    회색 제안이 전혀 나오지 않습니다

    VS Code에 Copilot 로그인이 되어 있는지 상태 표시줄 Copilot 아이콘으로 확인합니다. 파일 끝에서 Enter를 누르고 1~2초 기다린 뒤 글자를 몇 개 입력해 보면 나오는 경우가 많습니다.

    되돌렸는데도 Changes에 rules.py가 남아 있습니다

    빈 줄이나 공백이 남아 있을 수 있습니다. 소스 제어에서 rules.py에 마우스를 올리고 Discard Changes를 누르면 GitHub에서 가져온 원래 상태로 돌아갑니다.
