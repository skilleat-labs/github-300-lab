    2교시. Copilot 기본기¶

    이번 교시의 목표

    인라인 제안, 인라인 채팅, Chat의 역할(Ask, Agent)을 구분해 쓰고, 결과를 검증해 버그를 고칠 수 있습니다.

    구간 시간
    이론 15분
    실습 2-1 ~ 2-3 35분

    실습 페이지:

    • 실습 2-1 인라인 제안과 다음 편집 제안
    • 실습 2-2 코드 설명 듣고 설명 주석 받기
    • 실습 2-3 버그 잡기와 커밋

    교안¶

    Copilot을 쓰는 네 가지 방법¶

    방법 어떻게 언제 크레딧
    인라인 제안 쓰는 중에 회색 글자, Tab으로 수락 코드, 문장을 이어 쓸 때 무제한
    인라인 채팅 ⌘I / Ctrl+I, 그 자리에서 요청 선택한 부분만 묻거나 고칠 때 차감
    Chat (Ask) Chat 보기에서 질문 설명, 조사, 비교 차감
    Chat (Agent) 할 일을 주면 직접 고치고 실행 여러 파일을 바꾸는 작업 차감

    Copilot을 쓰는 방법은 크게 네 가지예요. 인라인 제안은 코드를 쓰는 중에 회색 글자로 다음 내용을 제안하는 거예요. Tab을 누르면 받아들이고 Esc를 누르면 무시해요. 인라인 채팅은 Command I나 Ctrl I로 지금 보고 있는 그 자리에서 요청해요. Chat은 옆 창에서 대화하는 건데, Ask 역할은 묻기만 하고 파일을 고치지 않고, Agent 역할은 직접 파일을 고치고 명령도 실행해요. 인라인 제안만 크레딧을 쓰지 않아요.

    인라인 제안: 의도를 먼저 쓰면 코드가 따라옵니다¶

    인라인 제안은 주석이나 함수 이름으로 의도를 먼저 쓰면 그다음 코드를 회색 글자로 제안해요. 마음에 들면 Tab, 아니면 Esc예요. 다음 편집 제안, 영어로 Next Edit Suggestions는 내가 한 곳을 고치면 그와 관련해 다음에 고칠 곳을 미리 제안해 주는 기능이에요. 예를 들어 변수 이름 하나를 바꾸면 같은 이름을 쓰는 다른 줄도 바꾸자고 제안해요. 둘 다 Pro에서는 무제한이라 크레딧 걱정 없이 써도 돼요.

    Chat은 묻기, 고치기, 계획 세우기로 씁니다¶

    Chat에서는 Agent 선택기로 Ask와 Agent 중 하나를 골라요. Ask는 묻기 전용이에요. 읽기만 하는 도구만 써서 파일을 바꾸지 않으니, 코드를 이해하거나 비교할 때 안심하고 쓰면 돼요. Agent는 실제로 파일을 고치고 터미널 명령도 실행하고 결과까지 확인해요. 계획 세우기는 선택기에 없어요. Copilot 하네스에서는 입력 칸에 /plan을 치고 요청을 이어 써요. 바로 고치지 않고 먼저 조사해서 구현 계획을 써 줘요. 예전 자료에 나오는 Edit 모드는 지금은 없어요.

    맥락을 직접 붙이면 답이 정확해집니다¶

    Copilot이 엉뚱한 답을 하는 가장 흔한 이유는 맥락이 부족해서예요. 맥락은 직접 붙일 수 있어요. 채팅 칸의 플러스 버튼으로 파일이나 이슈를 고르거나, 탐색기에서 파일을 끌어다 놓아요. 샵을 치면 맥락 목록이 나오는데, #codebase는 프로젝트 전체에서 관련 코드를 찾아 줘요. 코드를 선택하고 물으면 그 부분이 맥락이 돼요. 예전 자료나 블로그에 나오는 @workspace는 지금 Copilot 하네스에서는 동작하지 않아요. #codebase를 쓰세요.

    키보드로 파일 붙이기

    입력 칸에 #와 파일 이름 일부를 치면(예: #rules) 파일 목록이 좁혀집니다. ↑ ↓로 고르고 Enter를 누르면 파일이 맥락으로 붙습니다. 마우스로 +를 누르거나 끌어다 놓지 않아도 됩니다.

    자주 쓰는 슬래시 명령¶

    명령 하는 일 오늘 쓰는 곳
    /explain 선택한 코드를 설명 2-2 이용률 보고서 읽기
    /fix 문제를 찾아 고칠 방법 제안 2-3 18시 버그
    /tests 테스트 만들기 4-2 경계값 테스트
    /doc 설명 주석 만들기 (인라인 채팅) 2-2 설명 주석 받기
    /plan 구현 계획 세우기 4-1 겹침 검사 계획

    채팅 칸에 슬래시를 치면 자주 쓰는 명령이 나와요. /explain은 코드 설명, /fix는 문제 고치기, /tests는 테스트 만들기, /doc은 설명 주석 만들기, /plan은 구현 계획이에요. 명령은 긴 프롬프트를 짧게 줄여 주는 거라, 그냥 말로 '이 코드 설명해 줘'라고 해도 돼요.

    VS Code 곳곳에서 Copilot을 부를 수 있습니다¶

    어디서 어떻게 무엇을 오늘
    편집기 오른쪽 클릭 → Explain 선택한 코드 설명 2-2
    편집기 오른쪽 클릭 → Generate Code → Generate Docs, Generate Tests 설명 주석, 테스트 만들기 2-2, 4-2
    터미널 ⌘I / Ctrl+I, 실패한 명령 옆 반짝이 아이콘 터미널에서 묻기, 오류 설명 필요할 때
    소스 제어 메시지 칸의 반짝이 아이콘 커밋 메시지 초안 2-3
    Chat ⌃⌘I / Ctrl+Alt+I, 파일 끌어다 놓기 여러 파일을 놓고 대화, 작업 맡기기 매 교시

    Copilot은 채팅 창에만 있지 않아요. 일하는 자리에서 바로 부를 수 있어요. 편집기에서 코드를 선택하고 오른쪽 클릭하면 Explain으로 설명을 받고, Generate Code 메뉴로 설명 주석이나 테스트를 만들어요. 터미널에서도 Command I나 Ctrl I로 물을 수 있고, 명령이 실패하면 옆에 나오는 반짝이 아이콘으로 오류 설명을 받아요. 소스 제어의 메시지 칸에 있는 반짝이 아이콘은 커밋 메시지 초안을 만들어요. 초안은 꼭 읽고 고쳐요. 다 외울 필요 없어요. 가이드 부록 'VS Code와 Copilot 한 장 정리'에 모아 두었어요.

    소스 제어: 바뀐 것을 보고, 되돌리고, 기록하고, 올리는 곳¶

    왼쪽 활동 막대의 가지 모양 아이콘을 누르면 소스 제어 보기가 열려요. Copilot이 파일을 고치면 가장 먼저 여기에 나타나요. 그래서 오늘 하루 Copilot의 결과를 검토하는 곳이 바로 여기예요. 1-3에서 Discard Changes로 되돌려 봤고, 2-3에서 처음 커밋하고 올려요. 1교시에 배운 push, pull은 여기의 Sync Changes 버튼 하나로 해요.

    부분 어디에 하는 일 같은 Git 명령
    메시지 입력 칸 맨 위 커밋에 남길 한 줄 설명. 반짝이 아이콘으로 Copilot 초안 받기
    Commit 버튼 입력 칸 아래 바뀐 것을 기록으로 남기기. 커밋한 뒤에는 Sync Changes로 바뀜 git add + git commit
    Changes 버튼 아래 목록 커밋하지 않은 변경 파일. 내가 고친 것도, Copilot이 고친 것도 여기 보임 git status
    파일 클릭 Changes 목록 바뀌기 전과 후를 비교(diff) git diff
    Discard Changes (굽은 화살표) 파일에 마우스를 올리면 그 파일을 마지막 커밋 상태로 되돌리기 git restore
    Sync Changes 커밋한 뒤 버튼 자리 GitHub의 새 커밋 받고 내 커밋 올리기 git pull + git push
    그래프 맨 아래 커밋 기록. main과 구름 표시가 같은 줄이면 GitHub와 같은 상태 git log

    단축키는 Windows Ctrl+Shift+G, Mac ⌃⇧G예요. 안 먹으면 아이콘을 눌러요.

    버그는 Agent에게, 한 일과 나온 결과부터 알려 줍니다¶

    버그를 고칠 때는 Agent 역할을 써요. 대신 "이거 고쳐 줘"처럼 짧게 말하지 말고 자세히 알려 줘요. 순서는 네 가지예요. 무엇을 했는지, 무엇이 나왔는지, 원래 무엇이 나와야 하는지, 지켜야 할 것이 무엇인지예요. Copilot은 내 화면을 보지 못하니까, 실행한 명령과 결과를 그대로 붙여 주는 게 가장 좋은 맥락이에요.

    순서 무엇을 쓰나 2-3의 예
    ① 한 일 실행한 명령, 누른 버튼 python -m booking add ... --start 17:00 --end 18:00
    ② 나온 결과 오류 메시지, 출력을 그대로 [예약 실패] 운영 시간(09:00~18:00) 밖입니다.
    ③ 원하는 결과 근거와 함께 운영 규칙 "18:00에 끝나는 예약은 가능". 17:30~18:30은 계속 막힘
    ④ 지킬 것 바꿀 범위 booking/rules.py만 고치고 data 폴더는 바꾸지 않음

    근거 문서와 고칠 파일은 #02_현행_업무.md, #rules.py처럼 붙여요. 실제 프롬프트는 실습 2-3 STEP 2에 있어요.

    Copilot도 틀립니다. 그래서 세 가지로 검증합니다¶

    Copilot은 그럴듯하지만 틀린 답을 낼 수 있어요. 언어 모델의 한계예요. 그래서 오늘은 결과를 세 가지로 검증해요. 첫째, 직접 실행해서 기대한 결과가 나오는지 봐요. 둘째, 현업 요청이나 회의록, 운영 규칙 같은 근거 문서와 맞는지 대조해요. 셋째, 테스트를 돌려요. PR을 열면 테스트가 자동으로 돌아요. 2-3에서 실제 버그로 이 세 가지를 다 해 봐요.
