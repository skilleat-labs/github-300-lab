    실습 2-2. 코드 설명 듣고 설명 주석 받기¶

    이 실습에서 할 일

    • 아무도 손대기 싫어하는 booking/report.py를 /explain으로 설명받습니다.
    • 인라인 채팅으로 특정 줄만 콕 집어 묻습니다.
    • 설명을 그대로 믿지 않고, 프로그램을 직접 실행해 숫자로 검증합니다.
    • /doc으로 설명 주석 초안을 받아 코드와 맞는지 읽습니다.

    예상 시간 약 12분

    준비¶

    • room-practice가 VS Code에 열려 있어야 합니다.
    • Chat 보기를 엽니다(Windows Ctrl+Alt+I, Mac ⌃⌘I). Session Target Copilot, 역할 Ask, 모델 Auto.
    • 이 실습은 끝날 때 파일을 바꾸지 않습니다. 설명 주석은 받아서 읽고 되돌립니다.

    STEP 1. report.py 열어 보기¶

    1. 탐색기에서 booking/report.py를 엽니다.
    2. 맨 위 주석 "예전 담당자가 만든 이용률 보고서. 동작은 하지만 아무도 손대고 싶어 하지 않는다."를 읽습니다.
    3. 코드를 훑어보며 t, c, a, b, lv 같은 한 글자 변수와 여러 겹의 if를 찾습니다.

    확인: 코드만 봐서는 무엇을 계산하는지 한눈에 알기 어렵다는 것을 느꼈습니다. 이런 코드가 실무에서 Copilot 설명이 가장 쓸모 있는 곳입니다.

    STEP 2. /explain으로 전체 설명 듣기¶

    1. report.py 편집기 안을 클릭하고 전체를 선택합니다(Windows Ctrl+A, Mac ⌘A).
    2. Chat 위쪽 +(New Chat)로 새 채팅을 엽니다. 역할이 Ask인지 확인합니다.

    3. Chat 입력 칸에 붙여 넣고 Enter를 누릅니다.

      /explain 선택한 코드가 무엇을 계산하는지 기획자가 이해할 수 있게 설명해 주세요. 이용률 "높음, 보통, 낮음, 없음"을 나누는 기준을 시간 숫자로 정확히 적어 주세요.

    4. 답을 끝까지 읽습니다.

    확인: 이런 내용이 나오면 됩니다.

    • 회의실마다 예약 건수와 예약된 총 시간을 더한다.
    • 총 시간이 6시간 넘으면 "높음", 2시간 넘으면 "보통", 그 이하는 "낮음", 예약이 없으면 "없음".

    오른쪽 클릭으로도 부를 수 있어요

    코드를 선택하고 오른쪽 클릭 → Explain을 눌러도 설명을 받습니다.

    STEP 3. 인라인 채팅으로 한 줄만 묻기¶

    인라인 채팅은 Chat 보기로 가지 않고 편집기 안에서 바로 묻는 방법입니다.

    1. report.py에서 lv = "높음"이 있는 줄을 클릭합니다.
    2. Windows는 Ctrl+I, Mac은 ⌘I를 누릅니다.

    3. 편집기 안에 작은 입력 칸이 열리면 아래 질문을 입력하고 Enter를 누릅니다.

      lv가 뭐야? 어떤 값이 들어가고 어디에 쓰여? 코드는 고치지 말고 설명만 해 줘.

    4. 답을 읽고, Esc를 눌러 인라인 채팅을 닫습니다.

    확인: lv가 이용률 등급(level)을 담는 변수이고, 마지막 result에 "이용률"로 들어간다는 설명이 나오면 됩니다.

    인라인 채팅이 코드를 바꾸자고 하면

    인라인 채팅은 편집기 안에서 바로 코드를 고치는 제안을 하기도 합니다. 이 실습에서는 바꾸지 않습니다. 변경 제안이 나오면 받아들이지 말고 닫습니다. 실수로 바뀌었으면 Windows Ctrl+Z, Mac ⌘Z로 되돌립니다.

    언제 무엇을 쓰나요?

    도구 단축키 이럴 때
    인라인 제안 (자동) 코드를 쓰는 중 다음 줄 받기
    인라인 채팅 Ctrl+I / ⌘I 지금 보는 줄, 선택한 부분만 묻거나 고치기
    Chat 보기 Ctrl+Alt+I / ⌃⌘I 여러 파일, 문서를 함께 놓고 길게 대화하기

    STEP 4. 직접 실행해 숫자로 검증하기¶

    설명이 맞는지 실제 결과와 대조합니다.

    1. 터미널을 엽니다(Windows Ctrl+`, Mac ⌃`).

    2. 아래 명령을 실행합니다.

      python -m booking report

      소회의실 A {'건수': 2, '시간': 2.5, '이용률': '보통'}
소회의실 B {'건수': 1, '시간': 1.0, '이용률': '낮음'}
중회의실 {'건수': 1, '시간': 2.0, '이용률': '낮음'}
대회의실 {'건수': 1, '시간': 2.0, '이용률': '낮음'}

    3. data/reservations.json을 열어 소회의실 A(R1)의 예약을 직접 셉니다.

      • 1 10:00~11:00 → 1시간¶

      • 5 16:00~17:30 → 1.5시간¶

      • 합계 2.5시간, 2건 → 2시간을 넘으므로 "보통"

    확인: 손으로 계산한 소회의실 A의 건수, 시간, 이용률이 출력과 같습니다.

    STEP 5. 설명이 틀리기 쉬운 곳 찾기¶

    중회의실은 정확히 2.0시간인데 "보통"이 아니라 "낮음"입니다.

    1. STEP 2의 Copilot 설명에서 "보통"의 기준을 다시 읽습니다.
    2. 설명이 "2시간 이상이면 보통"이었는지, "2시간을 넘으면 보통"이었는지 확인합니다.
    3. 코드의 if t / 60 > 2: 줄과 비교합니다. >는 "넘으면"(2시간 정각은 포함 안 함)입니다.

    확인: 중회의실 2.0시간이 "낮음"인 이유를 코드의 > 2로 설명할 수 있습니다. Copilot 설명이 "이상"이라고 했다면, 그것이 바로 그럴듯하지만 틀린 설명입니다.

    Copilot 설명이 틀리기 쉬운 지점

    • 경계값: "넘으면"과 "이상", "미만"과 "이하"를 섞어 말하기 쉽습니다.
    • 범위: 이 보고서는 날짜를 나누지 않고 모든 날짜의 예약을 합칩니다. "하루 이용률"이라고 설명하면 틀린 것입니다.
    • 빠진 경우: start나 end가 비어 있거나 끝이 시작보다 빠른 예약은 건수에서 빠집니다.

    숫자가 들어간 설명은 항상 실제 실행 결과 한두 개로 대조해 봅니다.

    STEP 6. /doc으로 설명 주석 받기¶

    코드 설명과 문서는 Copilot이 초안을 쓰기 좋은 일입니다. 틀린 설명이 문서로 남지 않게 읽는 것은 사람의 몫입니다.

    1. report.py에서 def usage_report 줄을 클릭합니다.
    2. Windows Ctrl+I, Mac ⌘I로 인라인 채팅을 엽니다.

    3. 입력하고 Enter를 누릅니다.

      /doc 이 함수가 무엇을 계산하는지 기획자가 읽을 수 있는 한국어 설명 주석을 써 주세요. 이용률 기준을 포함해 주세요.

    4. 제안된 주석을 읽습니다. 기준이 "2시간을 넘으면 보통"인지 STEP 5에서 본 코드와 비교합니다.

    5. 받지 않고 인라인 채팅을 닫습니다. 소스 제어 Changes에 report.py가 있으면 Discard Changes를 누릅니다.

    확인: 주석 초안을 읽고 기준이 코드와 맞는지 판단했습니다. report.py는 바뀌지 않았습니다.

    다른 방법

    오른쪽 클릭 → Generate Code → Generate Docs로도 받습니다. 오늘 오후에는 클라우드 에이전트에게 사용 설명 문서를 맡겨 봅니다.

    다 됐는지 확인¶

    • report.py 전체를 선택하고 /explain으로 설명을 받았습니다.
    • 인라인 채팅(Ctrl+I / ⌘I)으로 lv에 대해 물었습니다.
    • python -m booking report를 실행하고, 소회의실 A의 숫자를 손으로 검증했습니다.
    • 중회의실 2.0시간이 "낮음"인 이유를 설명할 수 있습니다.
    • /doc으로 받은 주석의 기준을 코드와 비교했습니다.
    • report.py는 바뀌지 않았습니다(소스 제어 Changes가 비어 있음).

    막히면¶

    /explain을 입력해도 반응이 없습니다

    /를 입력하면 슬래시 명령 목록이 뜹니다. 목록에서 explain을 고른 뒤 나머지 문장을 붙여 넣습니다. 새 채팅에서 다시 해 봅니다.

    설명이 report.py가 아닌 다른 파일 이야기입니다

    선택이 풀린 상태로 물은 경우입니다. report.py 편집기를 클릭하고 다시 전체 선택한 뒤 묻거나, report.py를 Chat 입력 칸에 끌어다 놓아 첨부합니다.

    Ctrl+I(⌘I)를 눌렀는데 Chat 보기가 열립니다

    편집기 안의 코드 줄을 먼저 클릭해서 커서가 편집기에 있어야 인라인 채팅이 열립니다.

    python -m booking report 결과가 위와 다릅니다

    이전 실습에서 add로 예약을 넣어 data/reservations.json이 바뀌었을 수 있습니다. 소스 제어에서 reservations.json에 마우스를 올리고 Discard Changes를 눌러 되돌린 뒤 다시 실행합니다.

    인라인 채팅이 코드를 바꿔 버렸습니다

    Windows Ctrl+Z, Mac ⌘Z로 되돌리거나, 소스 제어에서 report.py의 Discard Changes를 누릅니다.
