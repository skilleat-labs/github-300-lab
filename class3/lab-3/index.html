    실습 3-3. 프롬프트 파일로 아이디어 검토하기¶

    이 실습에서 할 일

    • 업무 아이디어를 검토하는 요청을 프롬프트 파일 .github/prompts/idea.prompt.md로 저장합니다.
    • Local 하네스 채팅에서 /idea로 실행해, 총무팀의 월간 집계 업무를 자동화할 아이디어를 검토합니다.
    • 내 업무 한 문장으로도 실행해 보고, 프롬프트 파일을 커밋해 재사용할 수 있게 합니다.

    예상 시간 약 11분

    프롬프트 파일이란¶

    구분 지침 파일 (3-2) 프롬프트 파일 (3-3)
    파일 .github/copilot-instructions.md .github/prompts/이름.prompt.md
    언제 쓰이나 모든 채팅에 항상 자동으로 내가 /이름으로 부를 때만
    무엇을 쓰나 지켜야 할 규칙 반복하는 작업 하나의 요청문

    좋은 검토 요청을 파일로 저장해 두면 /idea 한 번으로 같은 형식의 결과를 받고, 팀과 나눠 쓸 수 있습니다.

    STEP 1. prompts 폴더와 파일 만들기¶

    1. 왼쪽 탐색기에서 .github 폴더를 마우스 오른쪽 버튼으로 클릭하고 New Folder...를 고릅니다.
    2. 폴더 이름에 prompts를 입력하고 Enter를 누릅니다.
    3. 방금 만든 prompts 폴더를 마우스 오른쪽 버튼으로 클릭하고 New File...을 고릅니다.

    4. 파일 이름에 아래를 입력하고 Enter를 누릅니다.

      idea.prompt.md

    확인: 탐색기에 .github/prompts/idea.prompt.md가 보입니다.

    명령으로 만드는 방법

    명령 팔레트(Windows Ctrl+Shift+P, Mac ⇧⌘P)에서 Chat: New Prompt File을 실행해도 됩니다. 이 리포지토리의 .github/prompts 폴더에 idea라는 이름으로 만듭니다.

    STEP 2. 프롬프트 내용 쓰기¶

    1. 아래 내용을 통째로 복사해 idea.prompt.md에 붙여 넣습니다.

      ---
description: 선택한 업무 설명으로 자동화 아이디어를 검토한다
agent: ask
---
아래 선택한 업무 설명을 읽고 자동화 아이디어를 검토해 주세요.

${selection}

형식:
### 아이디어 3개
표로 씁니다. 열은 아이디어, 줄어드는 일, 만드는 난이도(상, 중, 하), 위험입니다.

### 먼저 만들 것
- 한 개를 고르고 이유를 씁니다.
- 가장 작은 첫 버전의 입력, 처리, 출력을 한 줄씩 씁니다.
- 결과가 맞는지 사람이 확인할 방법을 씁니다.

### 확인 필요
선택한 글에 없어서 정하지 못한 것을 적습니다. 없으면 "없음".

규칙:
- 선택한 글에 없는 숫자나 효과를 지어내지 않습니다.
- 개인정보, 회사 자료를 다루면 위험에 적습니다.
- 한국어로 씁니다.

    2. 저장합니다(Windows Ctrl+S, Mac ⌘S).

    확인: 파일 맨 위가 ---로 시작하고, description과 agent: ask 두 줄 뒤에 다시 ---가 있습니다.

    각 부분의 뜻

    • 맨 위 --- 사이를 머리말이라고 합니다. description은 / 목록에 보이는 설명, agent: ask는 Ask 역할로 실행하라는 뜻입니다(agent, plan도 쓸 수 있습니다).
    • ${selection}은 실행할 때 편집기에서 선택한 글로 바뀌는 자리입니다.
    • 명령 이름은 파일 이름에서 옵니다. idea.prompt.md → /idea.

    STEP 3. 업무 설명 선택하기¶

    1. 탐색기에서 docs/04_월간집계_업무.md를 엽니다.
    2. "지금 하는 일"부터 "정하지 못한 것" 끝까지 마우스로 끌어 선택합니다.

    확인: 편집기에서 그 부분이 파랗게 선택되어 있습니다. 다음 STEP을 하는 동안 선택을 풀지 않습니다.

    STEP 4. Local 하네스에서 /idea 실행하기¶

    프롬프트 파일은 Local 하네스에서만 실행됩니다

    지금까지 쓴 Copilot 하네스 채팅에서는 /idea가 실행되지 않습니다. Session Target을 Local로 바꾼 새 채팅에서 실행합니다.

    1. Chat 보기에서 +(New Chat)를 클릭합니다.
    2. Session Target 컨트롤에서 Local을 고릅니다.
    3. 모델이 Auto인지 확인합니다.
    4. 입력 칸에 /를 입력하고, 목록에서 idea를 고릅니다.
    5. Enter를 누릅니다.

    확인: 아이디어 3개와 먼저 만들 것이 나옵니다. "부서별 노쇼 순위를 전사에 공유해도 되는가"가 확인 필요에 들어가 있으면 잘 된 것입니다. 정해 버렸거나 문서에 없는 절감 시간을 지어냈다면 사람이 지웁니다.

    화면이 조금 다를 수 있어요

    /를 입력해 목록에서 고르는 대신 명령 팔레트의 Chat: Run Prompt로 idea를 골라도 됩니다. Local 채팅은 VS Code 창을 닫으면 멈춥니다.

    STEP 5. 내 업무로 한 번 더¶

    1. 새 파일을 엽니다. File → New Text File

    2. 내 업무에서 반복하는 일을 두세 문장으로 씁니다. 회사 이름, 고객 정보, 실제 수치는 쓰지 않습니다.

      (예) 매주 월요일 부서별 진행 현황을 엑셀 세 개에서 모아 표 하나로 만들어 팀장에게 보낸다. 한 시간쯤 걸린다.

    3. 쓴 글을 선택하고 Local 채팅에서 다시 /idea를 실행합니다.

    4. 결과를 읽고, 이 파일은 저장하지 않고 닫습니다.

    확인: 내 업무에 대한 "먼저 만들 것"과 "확인 필요"를 받았습니다. 이 결과는 7-2에서 다시 씁니다. 필요하면 메모해 둡니다.

    STEP 6. 커밋하기¶

    1. Session Target을 다시 Copilot으로 돌려 둡니다(다음 교시부터는 Copilot 하네스를 씁니다). +(New Chat) 후 Session Target에서 Copilot을 고르면 됩니다.
    2. 소스 제어(Windows Ctrl+Shift+G, Mac ⌃⇧G)를 엽니다.
    3. Changes에 idea.prompt.md만 있는지 확인합니다.

    4. 메시지 칸에 아래를 입력하고 Commit, 이어서 Sync Changes를 누릅니다.

      아이디어 검토 프롬프트 파일 추가

    확인: github.com의 room-practice에서 .github/prompts/idea.prompt.md가 보입니다.

    팀에서 재사용하기

    프롬프트 파일을 리포지토리에 커밋하면 이 리포지토리를 가져간 팀원 모두가 같은 /idea를 씁니다.

    프롬프트 파일은 Local 하네스에서만 실행되므로, Copilot 하네스 같은 다른 하네스에서도 재사용하려면 에이전트 스킬(.github/skills/<이름>/SKILL.md)을 씁니다.

    다 됐는지 확인¶

    • .github/prompts/idea.prompt.md에 머리말(description, agent: ask)과 ${selection}이 있습니다.
    • Session Target Local 새 채팅에서 /idea를 실행했습니다.
    • 결과에서 문서에 없는 내용을 지어내지 않았는지 확인했습니다.
    • 내 업무 문장으로도 실행해 봤습니다.
    • 프롬프트 파일을 커밋하고 GitHub에 올렸습니다.
    • Session Target을 다시 Copilot으로 돌려 두었습니다.

    막히면¶

    먼저 Copilot과 함께 해결합니다

    오류 메시지나 막힌 상황을 Chat(Ask)에 붙여 넣고 원인과 해결 순서를 묻습니다. 아래는 자주 막히는 경우입니다. 묻는 방법은 막혔을 때에 있습니다.

    /를 입력해도 idea가 목록에 없습니다
    1. Session Target이 Local인지 확인합니다. Copilot 하네스에서는 프롬프트 파일이 실행되지 않습니다.
    2. 파일 위치가 .github/prompts/idea.prompt.md인지, 이름이 .prompt.md로 끝나는지 확인합니다.
    3. 파일을 저장했는지 확인하고 새 채팅을 엽니다.
    선택한 글이 아니라 엉뚱한 내용으로 답합니다

    /idea를 실행하기 전에 편집기 선택이 풀린 경우입니다. 글을 다시 선택한 뒤, 편집기를 클릭하지 말고 바로 Chat 입력 칸에서 실행합니다.

    머리말이 글자로 그대로 보이거나 설명이 목록에 안 나옵니다

    파일 첫 줄이 정확히 ---인지 봅니다. 앞에 빈 줄이나 공백이 있으면 머리말로 인식되지 않습니다.

    Session Target에 Local이 보이지 않습니다

    +(New Chat)를 먼저 눌러 새 채팅을 연 뒤 Session Target 컨트롤을 엽니다. 그래도 없으면 VS Code 버전(1.116 이상)을 확인합니다. Help → Check for Updates로 최신으로 올린 뒤 다시 엽니다.
