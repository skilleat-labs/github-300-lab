    실습 3-2. 지침 파일 만들기¶

    이 실습에서 할 일

    • 내가 원하는 규칙을 말하고 Copilot과 대화하며 지침 파일 .github/copilot-instructions.md를 만듭니다. 결과는 사람이 검토합니다.
    • 지침 파일이 없을 때와 있을 때, 같은 질문에 대한 Copilot 답을 비교합니다.
    • 응답의 References에서 지침 파일이 실제로 쓰였는지 확인하고 커밋합니다.

    예상 시간 약 12분

    지침 파일이란¶

    매번 프롬프트에 "한국어로 답해 줘", "회의록에 없는 정책은 지어내지 마"를 붙이기는 번거롭습니다. 지침 파일(custom instructions)에 한 번 써 두면 이 리포지토리의 모든 채팅에 자동으로 함께 들어갑니다.

    파일 위치 적용 범위
    .github/copilot-instructions.md 리포지토리 이 리포지토리의 모든 채팅 (오늘 만들 것)
    AGENTS.md 리포지토리 루트 위와 같은 용도의 다른 이름
    ~/.copilot/copilot-instructions.md 내 PC 나 혼자, 모든 프로젝트

    리포지토리에 넣고 커밋하면 팀 전체가 같은 지침을 씁니다.

    왜 .github 폴더에, 왜 .md 파일로 쓰나요?

    .github 폴더

    • .github는 GitHub와 도구가 읽는 설정을 모아 두는 폴더입니다. 오늘 쓰는 자동 테스트 .github/workflows/ci.yml도 여기에 있습니다.
    • Copilot은 정해진 자리에서 지침을 찾습니다. 리포지토리의 .github/copilot-instructions.md가 그 자리입니다. 이름이나 위치가 다르면 읽지 않습니다.
    • 리포지토리 안에 있으니 커밋하면 팀원 모두가 같은 지침을 받습니다. 바뀐 이력도 커밋으로 남습니다.
    • 이름 앞의 점(.)은 "설정용 폴더"라는 표시입니다. Mac의 Finder에서는 기본으로 숨겨져 보이지 않지만, VS Code 탐색기에는 보입니다.

    .github 폴더에 두는 대표 파일 (GitHub 공식 문서 기준)

    파일 하는 일 위치 규칙
    .github/workflows/*.yml GitHub Actions 워크플로 (오늘 ci.yml, pages.yml) 이 폴더에만 둡니다
    .github/copilot-instructions.md Copilot 리포지토리 지침 (3-2) 이 위치에만 둡니다
    .github/instructions/*.instructions.md 특정 파일에만 적용하는 Copilot 지침 이 폴더 아래
    .github/dependabot.yml 의존성 자동 업데이트 설정 이 폴더에만 둡니다
    .github/ISSUE_TEMPLATE/ 이슈를 만들 때 나오는 양식 이 폴더
    pull_request_template.md PR을 만들 때 나오는 양식 .github, 루트, docs 중 하나
    CODEOWNERS 파일별 리뷰 담당자 .github, 루트, docs 중 하나. 여러 곳에 있으면 .github가 먼저
    CONTRIBUTING.md, SECURITY.md 등 기여 방법, 보안 신고 안내 .github, 루트, docs 중 하나. .github가 먼저

    정리하면, 어떤 파일은 .github에만 두어야 하고, 어떤 파일은 여러 곳 중 하나를 고를 수 있지만 겹치면 .github가 먼저 쓰입니다. 그래서 GitHub와 도구를 위한 설정은 .github에 모아 두는 것이 일반적입니다. 문서에서는 이 폴더를 "숨김 폴더(hidden directory)"라고도 부릅니다.

    .md(Markdown) 파일

    • Markdown은 # 제목, - 목록 같은 간단한 기호로 구조를 표시하는 글 형식입니다. 메모장으로 열어도 그대로 읽힙니다.
    • 사람도 읽기 쉽고, Copilot 같은 언어 모델도 제목과 목록으로 나뉜 글을 잘 따릅니다.
    • GitHub 웹 화면에서 열면 제목과 목록이 보기 좋게 표시됩니다. 오늘 쓰는 docs/ 문서와 README도 모두 Markdown입니다.
    • 프로그램 문법이 아니라 글이라서, 개발을 몰라도 규칙을 쓰고 고칠 수 있습니다.

    STEP 1. 지침 파일 없이 먼저 물어보기 (전)¶

    1. Chat에서 +(New Chat)로 새 채팅을 엽니다. Session Target Copilot, 역할 Ask, 모델 Copilot Fusion.

    2. Chat에 붙여 넣고 Enter를 누릅니다.

      한 번에 너무 오래 예약하지 못하게 최대 예약 시간 검사를 booking/rules.py에 넣으려고 합니다. 어떻게 바꾸면 되는지 알려 주세요.

    3. 답에서 아래 두 가지를 메모해 둡니다.

      • 최대 시간을 몇 시간으로 정했나요? (2시간, 4시간 등)
      • 답이 한국어인가요, 오류 메시지 문장은 한국어인가요?

    확인: 메모를 했습니다. 대부분 최대 시간을 스스로 정해서 코드를 보여 줍니다. 회의록에서는 아직 정하지 못한 정책인데도요.

    STEP 2. Copilot과 대화하며 지침 만들기¶

    지침 파일은 내용을 복사해 오는 것이 아니라, 내가 원하는 규칙을 말하고 Copilot과 다듬어 만드는 것입니다. 실무에서 내 리포지토리의 지침을 만들 때도 같은 방법을 씁니다.

    1. +(New Chat)로 새 채팅을 엽니다. Session Target Copilot, 역할 Ask.

    2. 입력 칸에 #codebase를 고르고, 이어서 붙여 넣고 Enter를 누릅니다.

      이 리포지토리에서 Copilot이 항상 따를 지침 파일 .github/copilot-instructions.md를 만들려고 합니다.
docs/ 문서와 코드를 읽고, 지침에 넣으면 좋을 규칙을 목록으로 제안해 주세요. 아직 파일은 만들지 마세요.

제가 꼭 넣고 싶은 것:
- 답변은 한국어로, 전문 용어는 처음 나올 때 쉬운 말로 풀어서
- 회의록이나 docs/ 문서에 없는 정책은 지어내지 말고, 누구에게 확인해야 하는지 질문
- 기능을 바꾸면 tests/ 폴더에 pytest 테스트를 함께 추가
- data/ 폴더의 파일은 내가 요청할 때만 바꾸기

제가 놓친 규칙이 있으면 질문 2~3개로 물어봐 주세요.

    3. 제안과 질문을 읽고 답합니다. 예를 들어 이렇게 답할 수 있습니다.

      오류 메시지는 한국어 문장으로 마침표로 끝내 주세요. 운영 시간 규칙은 docs/02_현행_업무.md에 있는 그대로 넣어 주세요. 나머지는 제안대로 좋습니다.

    4. 제안 중에 문서에 없는 정책(예: "최대 예약은 2시간")이 들어 있으면 빼 달라고 말합니다. 지침에 잘못 들어간 정책은 이후 모든 답에 따라다닙니다.

    확인: 내가 원한 규칙 4개와 내가 고른 규칙만 남은 목록을 받았습니다.

    왜 Ask로 먼저 하나요?

    바로 파일을 만들게 하면 Copilot이 정한 규칙이 그대로 들어갑니다. Ask로 목록을 받아 사람이 고른 뒤에 파일을 만듭니다. 3교시에 배운 "목표, 맥락, 형식, 제약"과 "모르면 질문하게 하기"를 지침 만들기에 그대로 쓰는 것입니다.

    STEP 3. 지침 파일로 저장하고 검토하기¶

    1. 역할을 Agent로 바꿉니다.

    2. 같은 채팅에 붙여 넣고 Enter를 누릅니다.

      지금까지 정한 규칙으로 .github/copilot-instructions.md를 만들어 주세요.
제목과 짧은 목록으로, 30줄 이내로 써 주세요. 확인할 수 있는 문장으로 써 주세요. 다른 파일은 바꾸지 마세요.

    3. 승인 요청을 읽고 Allow Once를 누릅니다.

    4. 탐색기에서 .github/copilot-instructions.md를 열어 읽습니다. 아래가 모두 들어 있는지 확인합니다.
      • 답변은 한국어
      • 문서에 없는 정책은 지어내지 않고 질문
      • 기능을 바꾸면 pytest 테스트 추가
      • data/ 파일은 요청할 때만 변경
      • 정하지 않은 정책(최대 예약 시간 같은 것)이 규칙으로 들어가 있지 않음
    5. 고칠 곳이 있으면 편집기에서 직접 고치거나, Chat에 고칠 점을 말합니다. 저장합니다(Windows Ctrl+S, Mac ⌘S).

    확인: .github 폴더 바로 아래에 copilot-instructions.md가 있고(workflows 폴더 안이 아님), 위 체크가 모두 됩니다.

    지침은 짧고 구체적으로

    지침 파일은 모든 채팅에 함께 들어갑니다. 길게 쓰면 맥락을 차지하고, 애매하게 쓰면 지켜지지 않습니다. "좋은 코드를 써라"보다 "오류 메시지는 한국어 문장으로, 마침표로 끝낸다"처럼 확인할 수 있게 씁니다.

    참고 예시: 다 만든 지침 파일은 이런 모습입니다

    내 결과와 비교해 봅니다. 시간이 모자라면 이 내용을 .github/copilot-instructions.md에 붙여 넣고 다음 STEP으로 가도 됩니다.

        # 회의실 예약 서비스 Copilot 지침

    ## 프로젝트
    - 사내 회의실 예약 서비스다. 공유 엑셀 예약을 대신한다.
    - 요구사항의 근거는 docs/ 폴더의 문서다. 현업 요청(00), 킥오프 회의록(01), 현행 업무(02), 사용자 스토리(03).
    - 예약 규칙 검사는 booking/rules.py의 validate()에 모은다.

    ## 답변
    - 답변은 한국어로 한다.
    - 이 리포지토리를 읽는 사람은 기획자와 운영 담당자가 많다. 전문 용어는 처음 나올 때 쉬운 말로 풀어 쓴다.

    ## 정책
    - 회의록이나 docs/ 문서에 없는 정책(최대 예약 시간, 노쇼 기준, 연락처 공개 등)은 지어내지 않는다. 정해지지 않았다고 알리고, 누구에게 확인해야 하는지 질문한다.
    - 운영 시간은 09:00~18:00이고 18:00에 끝나는 예약은 가능하다. 예약은 30분 단위다.

    ## 코드
    - Python 3.12 기준으로 작성한다.
    - 사용자에게 보이는 오류 메시지는 한국어 문장으로, 마침표로 끝낸다. 예: "정원을 넘었습니다."
    - 기능을 바꾸면 pytest 테스트를 tests/ 폴더에 함께 추가한다. 테스트 함수 이름은 한국어로 동작을 설명한다. 예: test_정원을_넘으면_막는다
    - 바꾼 뒤에는 python -m pytest로 확인한다.

    ## 하지 말 것
    - data/reservations.json, data/rooms.json은 사용자가 요청할 때만 바꾼다.
    - 요청받지 않은 파일은 고치지 않는다.
    파일을 직접 만들거나 명령으로 만들려면
    • 탐색기에서 .github 폴더를 오른쪽 클릭 → New File... → copilot-instructions.md
    • 명령 팔레트에서 Chat: New Instructions File
    • 명령 팔레트에서 Chat: Open Customizations를 열면 지침, 스킬, 에이전트를 한곳에서 보고 만들 수 있습니다.

    STEP 4. 새 채팅에서 같은 질문하기 (후)¶

    지침은 새 채팅부터 적용됩니다.

    1. +(New Chat)로 새 채팅을 엽니다. 역할 Ask.

    2. STEP 1과 똑같은 질문을 붙여 넣고 Enter를 누릅니다.

      한 번에 너무 오래 예약하지 못하게 최대 예약 시간 검사를 booking/rules.py에 넣으려고 합니다. 어떻게 바꾸면 되는지 알려 주세요.

    3. 답에서 References(참조) 부분을 펼칩니다.

    확인: References 목록에 copilot-instructions.md가 보입니다. 이것이 지침 파일이 이번 답에 들어갔다는 증거입니다.

    STEP 5. 전과 후 비교하기¶

    STEP 1에서 메모한 것과 비교합니다.

    비교 지침 없음 (STEP 1) 지침 있음 (STEP 4)
    최대 시간 스스로 정한 숫자 "아직 정해지지 않았다", "강도윤 팀장에게 확인" 같은 질문
    오류 메시지 영어이거나 제각각 한국어 문장
    테스트 언급 없음 tests/에 pytest 테스트를 추가하자는 내용

    확인: STEP 4의 References에 지침 파일이 있고, 답이 최대 시간을 지어내지 않았습니다. 지침 없이도 답이 적절했다면 차이가 없어도 정상입니다. 차이를 만들려고 다시 시도하지 않습니다.

    지침은 '항상 지키는 규칙'이 아닙니다

    지침 파일은 Copilot에게 주는 강한 힌트이지, 반드시 지키는 잠금장치가 아닙니다. 중요한 규칙은 사람의 검토와 테스트로 한 번 더 확인합니다.

    STEP 6. 커밋하기¶

    1. 소스 제어(Windows Ctrl+Shift+G, Mac ⌃⇧G)를 엽니다.
    2. Changes에 copilot-instructions.md만 있는지 확인합니다.

    3. 메시지 칸에 아래를 입력하고 Commit, 이어서 Sync Changes를 누릅니다.

      Copilot 지침 파일 추가

    확인: github.com의 room-practice에서 .github/copilot-instructions.md가 보입니다.

    다 됐는지 확인¶

    • Copilot에게 규칙을 제안받고, 내가 고른 규칙으로 지침 파일을 만들었습니다.
    • 문서에 없는 정책이 지침에 들어가지 않았는지 검토했습니다.
    • .github/copilot-instructions.md가 .github 바로 아래에 있습니다.
    • 새 채팅의 References에서 지침 파일을 확인했습니다.
    • 같은 질문에 대해 지침 전과 후의 답을 비교했습니다.
    • 지침 파일을 커밋하고 GitHub에 올렸습니다.

    막히면¶

    먼저 Copilot과 함께 해결합니다

    오류 메시지나 막힌 상황을 Chat(Ask)에 붙여 넣고 원인과 해결 순서를 묻습니다. 아래는 자주 막히는 경우입니다. 묻는 방법은 막혔을 때에 있습니다.

    References에 지침 파일이 보이지 않습니다
    1. 파일 위치가 .github/copilot-instructions.md인지 확인합니다. .github/workflows/ 안에 만들었으면 탐색기에서 끌어 .github 폴더로 옮깁니다.
    2. 파일 이름의 철자(copilot-instructions.md, s 포함)를 확인합니다.
    3. 파일을 저장했는지 확인합니다.
    4. 기존 채팅이 아니라 새 채팅에서 물어야 합니다.
    탐색기에 .github 폴더가 안 보입니다

    탐색기 맨 위에 ROOM-PRACTICE가 보이는지 확인합니다. 다른 폴더를 열었다면 File → Open Folder로 room-practice를 엽니다.

    지침을 넣었는데도 최대 시간을 정해 버립니다

    Copilot 답은 매번 다릅니다. 새 채팅에서 한 번 더 물어봅니다. 그래도 같으면 지침의 "정책" 문장을 더 구체적으로 고칩니다. 예: "최대 예약 시간은 아직 정해지지 않았다. 코드에 숫자를 넣지 말고 먼저 질문한다."

    답이 여전히 영어로 나옵니다

    지침 파일이 적용되지 않은 경우입니다. 위의 References 항목을 차례로 확인합니다.
