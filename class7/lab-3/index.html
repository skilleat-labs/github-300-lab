    실습 7-3. 팀 규칙, 활용 사례 공유와 오늘의 정리¶

    이 실습에서 할 일

    • 팀 리포지토리에 지침 파일 .github/copilot-instructions.md를 만들어 팀의 Copilot 사용 규칙을 넣습니다.
    • 오늘 잘 통한 프롬프트를 모아 팀 활용 사례 docs/활용사례.md로 남기고 다른 팀과 나눕니다.
    • 새 채팅에서 지침이 적용되는지 References로 확인합니다.
    • 오늘 배운 기능을 교시별로 정리하고 GH-300 시험 범위와 연결합니다.

    소요 시간 약 13분 (규칙과 활용 사례 5분, Copilot PR 확인 3분, 정리와 공유 5분) 실습 장소 팀 리포지토리 room-booking-team<번호> 관련 교안 7교시 교안, 실습 3-2 지침 파일

    준비¶

    • 3교시 3-2에서 개인 리포지토리에 지침 파일을 만들어 봤습니다. 팀 리포지토리는 템플릿에서 새로 만들어 지침 파일이 없습니다.
    • 작업은 PM 한 명이 VS Code에서 하고, 팀은 규칙을 같이 정합니다.

    STEP 1. (팀 함께) 규칙 정하기¶

    오늘 하루 Copilot을 쓰며 겪은 일을 떠올려 팀 규칙 4~6개를 정합니다. 아래는 예시입니다. 팀이 고르고 고칩니다.

    오늘 겪은 일 규칙 예
    현황판에 연락처가 그대로 공개됨 (6-3) 공개 현황판에는 연락처와 전체 이름을 표시하지 않는다
    테스트로 경계값 실수를 잡음 (4-2, 5-2) 모든 코드 변경에는 테스트를 함께 추가한다
    결정 못 한 정책을 강사에게 물음 (5-1) 회의록과 이슈에 없는 정책은 지어내지 말고 "확인 필요"로 표시한다
    Copilot 리뷰는 댓글일 뿐 (6-1) Copilot이 만든 변경은 사람이 검토하고 승인한 뒤 병합한다
    제목에 스크립트가 들어감 (7-1) 사용자가 입력한 값은 HTML에 넣기 전에 html.escape()로 처리한다
    실습 데이터가 커밋에 섞일 뻔함 data/ 파일은 기능 변경과 같이 커밋하지 않는다

    그리고 팀원마다 오늘 가장 잘 통한 프롬프트 하나를 말합니다. 어느 상황에 썼고 왜 좋았는지도 말합니다.

    확인: 팀 규칙 4~6개와 활용 사례를 정했습니다.

    STEP 2. (PM) 지침 파일 만들기¶

    1. VS Code에서 main을 최신으로 맞추고, 상태 표시줄 브랜치 이름 클릭 → Create new branch...로 브랜치를 만듭니다.

      team-rules

    2. Chat +(New Chat) → Session Target Copilot, Agent Agent를 고릅니다.

    3. Chat에 붙여 넣기. 규칙 부분은 STEP 1에서 팀이 정한 것으로 바꿉니다.

      .github/copilot-instructions.md 파일을 만들어 주세요. 이 리포지토리에서 Copilot이 항상 따를 팀 규칙입니다. 한국어로, 짧은 목록으로 써 주세요.

## 프로젝트
- 사내 회의실 예약 서비스. Python 3.12, 테스트는 pytest(python -m pytest).
- 예약 규칙은 booking/rules.py, 현황판은 build_site.py.

## 팀 규칙
- 공개 현황판에는 연락처와 전체 이름을 표시하지 않는다. 예약자는 성과 ○○로만 보인다.
- 모든 코드 변경에는 테스트를 함께 추가한다.
- 회의록과 이슈에 없는 정책은 지어내지 말고 "확인 필요"로 표시한다.
- 사용자가 입력한 값은 HTML에 넣기 전에 html.escape()로 처리한다.
- Copilot이 만든 변경은 사람이 검토하고 승인한 뒤 병합한다.

docs/활용사례.md 파일도 만들어 주세요. 표로 쓰고 열은 상황, 프롬프트, 좋았던 점, 주의할 점입니다. 내용은 아래만 씁니다.
(팀원들이 말한 프롬프트를 여기에 붙여 넣기)

이 두 파일 외에는 바꾸지 마세요.

    4. 만들어진 파일을 열어 팀이 정한 규칙이 그대로 들어갔는지 읽습니다. Copilot이 팀이 정하지 않은 규칙을 덧붙였으면 지웁니다.

    확인: .github/copilot-instructions.md에 팀 규칙만, docs/활용사례.md에 팀이 말한 사례만 들어 있습니다.

    직접 만들어도 됩니다

    명령 팔레트에서 Chat: New Instructions File을 실행해 직접 만들 수도 있습니다. 3-2에서 개인 room-practice에 만든 지침 파일 내용을 복사해 와서 팀 규칙을 덧붙여도 됩니다.

    STEP 3. 지침이 적용되는지 확인하기¶

    1. Chat +(New Chat)를 클릭합니다. Agent Ask를 고릅니다.

    2. Chat에 붙여 넣기

      현황판에 예약자 연락처를 다시 보여 주려면 build_site.py를 어떻게 고치면 되나요?

    3. 답 아래 References(참조)를 펼칩니다.

    확인: References에 .github/copilot-instructions.md가 있고, 답이 개인정보 규칙을 언급하거나 확인이 필요하다고 말합니다.

    지침은 항상 지켜지는 것이 아닙니다

    지침 파일은 Copilot Chat과 에이전트가 매번 함께 읽는 맥락입니다. 따를 가능성을 높여 줄 뿐, 반드시 지킨다는 보장은 아닙니다. 그래서 규칙에 "사람이 검토한다"가 꼭 들어갑니다.

    STEP 4. 커밋, PR, 병합¶

    1. 소스 제어에서 바뀐 파일이 .github/copilot-instructions.md와 docs/활용사례.md인지 보고 커밋합니다.

      팀 Copilot 사용 규칙과 활용 사례 추가

    2. Publish Branch → github.com에서 PR을 엽니다.

    3. 팀원 한 명이 규칙을 읽고 Approve, PM이 테스트 / test 초록을 보고 병합합니다.
    4. 팀원 모두 VS Code에서 main으로 돌아와 동기화합니다.

    확인: main에 .github/copilot-instructions.md가 있습니다. 병합으로 현황판 배포도 한 번 더 돌지만 현황판 내용은 그대로입니다.

    STEP 5. (팀 함께) 맡겨 둔 Copilot PR 확인하기¶

    1. Pull requests 탭에서 5-3에서 맡긴 작업의 PR이 열렸는지 봅니다.
    2. 열렸고 Copilot이 리뷰를 요청했으면 미션 5-3의 PR 검토 순서대로 진행합니다. 변경 읽기 → Approve and run workflows → 테스트 확인 → Ready for review → 맡긴 사람이 아닌 팀원이 승인 → 병합.
    3. 아직 진행 중이면 기다리지 않고 정리로 넘어갑니다.

    확인: PR 상태를 팀이 알고 있고, 끝나지 않았다면 언제 볼지 정했습니다.

    오늘의 정리¶

    팀마다 30초씩 활용 사례 하나를 전체에 공유합니다.

    교시 배운 기능 오늘 해 본 것
    1 VS Code 내장 Copilot Chat, 로그인, Copilot settings, 하네스(Copilot), 모델 Copilot Fusion 공개 코드 일치, 학습 데이터 설정, 첫 질문
    2 인라인 제안(Tab, Esc), 다음 편집 제안(NES), 인라인 채팅, /explain, /fix, 역할 Ask와 Agent 18시 버그 고치고 커밋
    3 프롬프트 전략, zero-shot과 few-shot, 지침 파일, 스킬(/idea) 회의록에서 사용자 스토리, 아이디어 검토
    4 /plan, Agent, 승인(Manual), 소스 제어 보기, Restore Checkpoint, /tests, PR Summary, CI 겹침 검사, PR, 병합
    5 맥락(#codebase, Add Context), 역할별 Copilot 활용, 클라우드 에이전트 이슈 S1~S4, 인수 조건, 각자 구현, 이슈 맡기기
    6 Copilot 코드 리뷰, 충돌 해결, Agent로 워크플로 만들기, CD(Pages) 현황판 자동 배포, CR-001
    7 보안 검토, 업무 자동화 도구 만들기, 팀 지침 XSS 수정, 월간 보고서, 팀 규칙과 활용 사례

    GH-300 시험 범위와 오늘의 실습¶

    시험 영역 (비중) 오늘 해 본 실습
    책임 있는 사용 (15~20%) 5-1 정책을 지어내지 않기, 6-1 Copilot 리뷰를 사람이 판단, 7-1 보안 검토, 7-3 팀 규칙
    Copilot 기능 사용 (25~30%) 2교시 인라인 제안과 채팅, 4교시 Plan과 Agent, 6-1 코드 리뷰, 5-3 클라우드 에이전트. 장표: Copilot CLI, 관리자 기능
    데이터와 구조 (10~15%) 1-1 하네스와 설정, 3-2 지침 파일, 5-1 #codebase 맥락. 장표: 제안이 만들어지는 과정
    프롬프트와 맥락 (10~15%) 3교시 프롬프트 전략, zero-shot과 few-shot, 지침 파일과 스킬
    생산성 (10~15%) /tests, /doc, PR Summary, CI와 CD, 7-2 자동화 도구와 "같은 방법으로 시킬 수 있는 일"
    개인정보, 콘텐츠 제외, 안전장치 (10~15%) 1-1 공개 코드 일치와 학습 데이터 설정, 6-3 연락처 제거. 장표: 콘텐츠 제외 설정, 출력물 소유

    콘텐츠 제외는 Pro에 없어요

    특정 파일을 Copilot이 읽지 못하게 하는 콘텐츠 제외(Content exclusion)는 Business, Enterprise 기능입니다. 오늘 쓴 Pro에는 없습니다. 시험에는 나오니 이름과 뜻은 알아 둡니다. 설정 위치와 감사 로그, 구독 관리, 시험 용어 정리는 7교시 교안의 시험 대비 장에 있습니다.

    다음에 배워 볼 것¶

    • MCP: Copilot에 외부 도구와 데이터를 연결하는 방법입니다. VS Code 명령 MCP: Add Server로 추가합니다. GitHub의 MCP 서버 원격 주소는 https://api.githubcopilot.com/mcp/입니다.
    • Copilot CLI: 터미널에서 Copilot과 일하는 도구입니다. copilot으로 실행하고, Shift+Tab으로 standard, plan, autopilot을 바꿉니다. Pro에 포함됩니다.

    다 됐는지 확인¶

    • 팀 규칙 4~6개를 정했다
    • .github/copilot-instructions.md와 docs/활용사례.md를 만들고 PR로 병합했다
    • 새 채팅의 References에 지침 파일이 보였다
    • 오늘 배운 기능을 교시별로 말할 수 있다
    • 5-3의 Copilot PR을 확인했다 (또는 다음 날 확인하기로 했다)

    막히면¶

    먼저 Copilot과 함께 해결합니다

    오류 메시지나 막힌 상황을 Chat(Ask)에 붙여 넣고 원인과 해결 순서를 묻습니다. 아래는 자주 막히는 경우입니다. 묻는 방법은 막혔을 때에 있습니다.

    References에 지침 파일이 안 보여요

    파일 위치가 리포지토리 루트의 .github/copilot-instructions.md인지 봅니다. 폴더 이름 앞의 점(.)이 빠지기 쉽습니다. 새 채팅을 열어 다시 물어봅니다.

    답이 지침을 무시하고 연락처를 보여 주는 코드를 줘요

    지침은 맥락일 뿐 강제가 아닙니다. 이런 결과를 사람이 리뷰에서 걸러야 한다는 것이 이 실습의 요점입니다. 지침 문장을 더 분명하게 고쳐 볼 수도 있습니다.

    Copilot이 지침 파일에 규칙을 더 많이 넣었어요

    팀이 정하지 않은 규칙은 지웁니다. 지침 파일도 팀이 검토하고 책임지는 문서입니다.

    PR을 만들었는데 다른 팀원 PR과 충돌해요

    .github/copilot-instructions.md는 새 파일이라 보통 충돌하지 않습니다. 충돌이 나면 미션 6-1 STEP 6처럼 두 내용을 모두 남깁니다.
