    미션 5-0. 팀 리포지토리 만들기¶

    이 실습에서 할 일

    • 팀 번호와 역할(PO, PM, BA, 개발자)을 받습니다.
    • PO가 템플릿으로 팀 리포지토리 room-booking-team<번호>를 만들고 팀원을 초대합니다. 팀원은 수락하고 각자 VS Code로 가져옵니다.
    • PO가 6교시 배포에 대비해 Pages 설정을 미리 바꿔 둡니다.

    소요 시간 약 8분 실습 장소 팀 리포지토리 room-booking-team<번호> 관련 교안 세 가지 방법, 계속 끌고 가는 법, 역할 카드

    이론에서 본 순서 그대로 합니다

    PO는 템플릿으로 팀 리포지토리를 만들고(STEP 1), 팀원을 협업자로 초대합니다(STEP 2). 팀원은 초대를 수락하고(STEP 4) 각자 clone합니다(STEP 5). 포크는 쓰지 않습니다. 포크는 쓰기 권한이 없는 리포에 기여할 때 쓰는 방법이라, 같은 리포를 함께 쓰는 팀에는 협업자 초대가 맞습니다.

    준비¶

    팀과 역할 받기¶

    강사가 팀 번호와 역할을 정해 줍니다. 17명 기준입니다.

    팀 인원 역할
    1~2팀 4명 PO, PM, BA, 개발자 각 1명
    3~5팀 3명 PO, BA(PM 겸임), 개발자 각 1명

    3인 팀은 BA가 PM을 겸합니다

    5~7교시 페이지에서 "PM"이라고 적힌 일은 BA가 합니다. 이슈를 만드는 사람이 인수 조건까지 바로 써서, 셋이 처음부터 동시에 일할 수 있게 나눈 것입니다. 팀 백로그도 S4를 빼고 3개만 합니다.

    사람 5교시에 하는 일
    PO 팀 리포 만들기와 초대(5-0), 우선순위와 현업 질문(5-1)
    BA (PM 겸임) 이슈 S1~S3 등록과 배정, 각 이슈에 인수 조건(5-1), 클라우드 에이전트에 맡기기(5-3)
    개발자 바꿀 파일과 충돌 위험 분석(5-1)

    셋 모두 스토리 하나씩 구현합니다(5-2). 팀에서 GitHub를 가장 익숙하게 쓰는 사람이 PO를 맡으면 5-0이 빨리 끝납니다.

    역할은 '누가 결정하고, 정리하고, 검토하나'입니다

    역할이 개발자가 아니어도 코드를 씁니다. 정확히는 모두가 Copilot에게 시켜서 스토리 하나씩 구현합니다. 역할은 그 외에 누가 우선순위를 결정하는지(PO), 이슈와 병합을 정리하는지(PM), 인수 조건으로 검토하는지(BA), 기술 위험을 보는지(개발자)를 나눈 것입니다.

    받은 내용을 메모해 둡니다. 이 페이지부터 <번호>는 내 팀 번호, <PO아이디>는 우리 팀 PO의 GitHub 아이디로 바꿔 읽습니다.

    우리 팀 번호:
내 역할:
PO 아이디:
PM 아이디:
BA 아이디:
개발자 아이디:

    전체 순서¶

    순서 누가 무엇을
    1 PO 템플릿으로 room-booking-team<번호> 만들기 (Public)
    2 PO Collaborators로 팀원 초대
    3 PO Settings → Pages → Source를 GitHub Actions로
    4 팀원 초대 수락
    5 모두 VS Code에서 Git: Clone으로 가져오고, 새 가상환경을 만들어 테스트 도구 설치, 테스트 실행

    STEP 1. (PO) 팀 리포지토리 만들기¶

    1. 브라우저 주소창에 Starter 템플릿 주소를 입력합니다.

      https://github.com/skilleat-labs/meeting-room-starter

    2. 오른쪽 위 초록 Use this template(이 템플릿 사용) → Create a new repository를 클릭합니다.

    3. Owner(소유자)가 내 아이디인지 봅니다.

    4. Repository name에 팀 번호를 넣어 입력합니다. 예: 3팀이면 room-booking-team3

      room-booking-team<번호>

    5. Public(공개)을 고릅니다. 무료 계정에서 Pages를 쓰려면 Public이어야 합니다.

    6. Create repository를 클릭합니다.

    확인: 주소가 github.com/<PO아이디>/room-booking-team<번호>이고 booking, docs, tests 폴더가 보입니다.

    STEP 2. (PO) 팀원 초대하기¶

    1. 팀 리포지토리에서 Settings(설정) 탭을 클릭합니다.
    2. 왼쪽 메뉴 Collaborators(협업자)를 클릭합니다. 비밀번호나 인증 확인 창이 뜨면 본인이 직접 확인합니다.
    3. Add people(사람 추가)을 클릭합니다.
    4. 팀원 아이디를 입력하고 목록에서 고른 뒤 Add 아이디 to this repository를 클릭합니다. 역할을 묻는 화면이 나오면 Write(쓰기)를 고릅니다.
    5. 팀원 수만큼 반복합니다. (4인 팀 3명, 3인 팀 2명)
    6. 팀원에게 "초대 보냈습니다"라고 말로 알립니다.

    확인: Collaborators 목록에 팀원이 모두 Pending invite(초대 대기) 또는 이름으로 보입니다.

    STEP 3. (PO) Pages 설정 미리 바꿔 두기¶

    6교시 미션 6-2에서 팀이 Copilot으로 배포 워크플로를 만듭니다. 그때 바로 배포되도록 설정만 먼저 바꿔 둡니다. 지금은 웹페이지가 열리지 않는 것이 정상입니다.

    1. Settings → 왼쪽 메뉴 Pages를 클릭합니다.
    2. Build and deployment(빌드와 배포) 아래 Source(소스)를 GitHub Actions로 바꿉니다.
    3. 아래에 추천 워크플로 카드가 나와도 누르지 않습니다. 6-2에서 Copilot으로 만듭니다.

    확인: Source가 GitHub Actions로 보입니다.

    STEP 4. (팀원) 초대 수락하기¶

    1. PO가 "초대 보냈습니다"라고 하면 GitHub 가입 이메일을 열거나 아래 주소로 이동합니다.

      https://github.com/<PO아이디>/room-booking-team<번호>/invitations

    2. Accept invitation(초대 수락)을 클릭합니다.

    확인: 팀 리포지토리가 열리고, 파일을 열었을 때 연필 아이콘(편집)이 보입니다.

    STEP 5. (모두) VS Code로 가져오기¶

    PO도 포함해 모두 각자 PC로 가져옵니다.

    1. 팀 리포지토리 화면에서 초록 Code → HTTPS 주소 옆 복사 아이콘을 클릭합니다.
    2. VS Code에서 명령 팔레트를 엽니다. Windows는 Ctrl+Shift+P, Mac은 Cmd+Shift+P
    3. Git: Clone을 입력하고 고릅니다.
    4. 복사한 주소를 붙여 넣고 Enter를 누릅니다.
    5. 저장 위치로 문서/copilot-lab 폴더를 고릅니다. room-practice와 나란히 놓입니다.
    6. 오른쪽 아래 Open(열기)을 클릭합니다. "작성자를 신뢰하느냐"는 창이 뜨면 Yes, I trust the authors를 누릅니다.

    7. 터미널을 엽니다(Windows Ctrl+`, Mac ⌃`). 현재 폴더가 room-booking-team<번호>인지 봅니다.

      가상환경을 새로 만들어야 합니다

      1-2에서 만든 가상환경은 room-practice 폴더 안에 있고, .venv는 커밋되지 않아 팀 리포지토리에는 없습니다. 이 폴더에서 새로 만들고 도구도 다시 설치합니다.

    8. 가상환경을 만듭니다. room-booking-team<번호> 폴더 안에 .venv 폴더가 생깁니다.

      python -m venv .venv

      python3 -m venv .venv

    9. 가상환경을 켭니다.

      .venv\Scripts\Activate.ps1

      source .venv/bin/activate

      확인: 터미널 줄 맨 앞에 (.venv)가 붙습니다. 오른쪽 아래에 새 환경을 이 작업 영역에 쓸지 묻는 알림이 뜨면 Yes를 누릅니다.

    10. 켜진 가상환경에 테스트 도구를 설치합니다.

      python -m pip install -r requirements-dev.txt

      python3 -m pip install -r requirements-dev.txt

      확인: 마지막 줄에 Successfully installed ... pytest ...가 나옵니다.

    11. 테스트를 실행합니다.

      python -m pytest

      python3 -m pytest

    확인: VS Code 탐색기 맨 위에 ROOM-BOOKING-TEAM<번호>가 보이고, 4 passed가 나옵니다.

    창을 헷갈리지 않게

    오후에는 팀 리포지토리 창만 씁니다. 개인 room-practice 창은 닫아도 됩니다. 7-1에서 다시 엽니다.

    오전에 만든 것은 따라오지 않아요

    팀 리포지토리는 템플릿에서 새로 만들었기 때문에 Starter와 같은 상태입니다. 2교시에 고친 18시 버그, 4교시에 넣은 겹침 검사, 3교시의 지침 파일과 스킬은 없습니다. 그래서 5교시에 팀이 S1~S4로 다시 만듭니다. 한 번 해 본 일이라 막히지 않습니다.

    다 됐는지 확인¶

    • 팀 번호와 역할을 메모했다
    • (PO) room-booking-team<번호>를 Public으로 만들었다
    • (PO) 팀원 모두 Collaborators에 있다
    • (PO) Pages Source가 GitHub Actions다
    • (팀원) 초대를 수락했다
    • (모두) VS Code에 팀 리포지토리를 가져와 새 가상환경 (.venv)을 만들었고, 테스트 4개가 통과한다

    막히면¶

    먼저 Copilot과 함께 해결합니다

    오류 메시지나 막힌 상황을 Chat(Ask)에 붙여 넣고 원인과 해결 순서를 묻습니다. 아래는 자주 막히는 경우입니다. 묻는 방법은 막혔을 때에 있습니다.

    Use this template 버튼이 안 보여요

    로그인이 안 되어 있거나 주소가 틀린 경우입니다. 오른쪽 위에 내 프로필 사진이 보이는지, 주소가 skilleat-labs/meeting-room-starter인지 확인합니다.

    초대 주소를 열었더니 404가 떠요

    PO가 아직 초대하지 않았거나 PO 아이디를 잘못 넣은 것입니다. PO의 Collaborators 목록에 내 아이디가 있는지 함께 봅니다.

    Pages 메뉴에 GitHub Actions가 없어요

    리포지토리가 Private이면 무료 계정에서 Pages를 못 씁니다. Settings → General 맨 아래 Danger Zone → Change visibility로 Public으로 바꿉니다. 이 작업은 PO가 직접 확인하고 합니다.

    Clone할 때 로그인 창이 떠요

    GitHub 계정으로 허용합니다. 1-2에서 로그인한 계정과 같아야 합니다.

    No module named pytest 라고 나와요

    이 리포에서 가상환경을 새로 만들지 않았거나, 켜지 않고 설치한 경우입니다. 터미널 앞에 (.venv)가 있는지 보고 STEP 5의 8~10번을 이 리포의 터미널에서 다시 실행합니다. 그래도 같으면 막혔을 때의 같은 항목을 봅니다.

    Windows에서 Activate.ps1이 '스크립트를 실행할 수 없으므로' 오류를 냅니다

    1-2와 같은 문제입니다. 실습 1-2 맨 아래 "막히면"의 같은 항목대로 합니다.

    5명 이상이거나 2명이에요

    강사에게 알립니다. 2명이면 다른 팀에 합류하고, 5명이면 한 명이 다른 팀으로 가거나 BA를 두 명으로 둡니다.
