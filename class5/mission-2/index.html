    미션 5-2. 스토리 구현¶

    이 미션에서 할 일

    • 모두 자기 이슈 번호로 브랜치 story-<번호>를 만들고, 4교시 흐름(계획 → Agent 구현 → 검토 → 직접 검증)으로 스토리를 구현합니다.
    • 인수 조건대로 직접 명령을 실행해 확인하고, 이슈 번호를 넣어 커밋한 뒤 GitHub에 올립니다.
    • PR은 6교시 미션 6-1에서 엽니다.

    소요 시간 약 25분 실습 장소 팀 리포지토리 room-booking-team<번호> (VS Code) 관련 교안 팀 백로그, 실습 4-2

    준비¶

    • 미션 5-1에서 내 이슈 번호를 메모했어야 합니다. 이 페이지는 #3을 예로 씁니다. story-3은 내 번호로 바꿔 읽습니다.
    • VS Code에서 팀 리포지토리가 열려 있고, 상태 표시줄 브랜치가 main인지 봅니다.

    모두 같은 흐름입니다

    역할이 PO든 BA든 이 미션에서 할 일은 같습니다. 4교시에 개인 리포지토리에서 한 실습 4-1~4-2를 팀 리포지토리에서 내 스토리로 다시 합니다.

    STEP 1. 내 브랜치 만들기¶

    1. 소스 제어의 동기화 아이콘을 눌러 main을 최신으로 맞춥니다.
    2. 상태 표시줄의 브랜치 이름 main을 클릭합니다.

    3. Create new branch...를 클릭하고 내 이슈 번호로 이름을 입력합니다.

      story-3

    확인: 상태 표시줄에 story-<내번호>가 보입니다.

    STEP 2. 이슈를 근거로 계획 받기¶

    1. Chat 보기 +(New Chat)를 클릭합니다. Session Target Copilot, 모델 Auto, 권한 Manual인지 봅니다.
    2. github.com에서 내 이슈를 열고 본문 전체(스토리, 바꿀 곳, 완료 기준, 인수 조건)를 복사합니다.

    3. Chat에 붙여 넣기. (여기에 이슈 본문) 자리에 복사한 내용을 넣습니다.

      /plan 아래 GitHub 이슈 #3을 구현하는 계획을 세워 주세요.
- 바꿀 파일과 함수
- 인수 조건마다 추가할 테스트 (tests/test_rules.py 또는 새 테스트 파일)
- 직접 확인할 python -m booking 명령
- 이슈에 없는 기능은 넣지 마세요.

(여기에 이슈 본문)

    4. 계획을 읽고, 인수 조건이 모두 테스트로 들어갔는지 봅니다. 빠졌으면 "인수 조건 ○번도 테스트에 넣어 주세요"라고 요청합니다.

    확인: 계획에 바꿀 파일, 인수 조건별 테스트, 확인 명령이 있습니다.

    이슈를 직접 첨부할 수도 있어요

    입력 칸 +(Add Context)에 Issue 항목이 있으면 이슈를 맥락으로 붙일 수 있습니다. 안 보이면 위처럼 본문을 붙여 넣습니다.

    STEP 3. Agent로 구현하고 테스트하기¶

    1. Agent 선택기를 Agent로 바꿉니다.

    2. Chat에 붙여 넣기

      위 계획대로 구현하고 테스트를 추가해 주세요.
- 기존 테스트는 지우거나 바꾸지 마세요.
- 다 되면 python -m pytest를 실행해 결과를 보여 주세요.
- 계획에 없는 파일은 바꾸지 마세요.

    3. 승인 요청이 뜨면 무엇을 실행하는지 읽고 승인합니다. 삭제 명령이나 git push는 승인하지 않습니다.

    4. 채팅의 바뀐 파일 목록이나 소스 제어 보기(Windows Ctrl+Shift+G, Mac ⌃⇧G)의 Changes 목록에서 diff를 읽습니다.

    5. 터미널에서 직접 테스트를 실행합니다.

      python -m pytest

    확인: failed가 없고, 내 스토리의 인수 조건마다 테스트가 있습니다. 바뀐 파일이 팀 백로그의 "바꿀 곳"과 테스트 파일뿐입니다.

    STEP 4. 인수 조건대로 직접 확인하기¶

    내 스토리 탭을 골라 명령을 실행합니다. 메시지 문장은 조금 달라도, 성공과 실패가 맞으면 됩니다. 예약 번호(#6 등)는 다를 수 있습니다.

    python -m booking add --room R1 --title 겹침 --date 2026-11-10 --start 10:30 --end 11:30 --booker 홍길동 --attendees 2

    [예약 실패]
 - 이미 예약된 시간입니다: #1 10:00~11:00 주간 업무 회의

    python -m booking add --room R1 --title 이어서 --date 2026-11-10 --start 11:00 --end 12:00 --booker 홍길동 --attendees 2

    [예약 완료] #6 2026-11-10 11:00~12:00 R1 이어서

    python -m booking add --room R1 --title 정원초과 --date 2026-11-13 --start 10:00 --end 11:00 --booker 홍길동 --attendees 5

    [예약 실패]
 - 정원을 넘었습니다: 소회의실 A 정원 4명, 참석 5명

    정원과 같은 인원은 성공해야 합니다.

    python -m booking add --room R1 --title 정원딱맞음 --date 2026-11-13 --start 10:00 --end 11:00 --booker 홍길동 --attendees 4

    [예약 완료] #6 2026-11-13 10:00~11:00 R1 정원딱맞음

    python -m booking cancel --id 3

    [취소 완료] #3

    python -m booking list --date 2026-11-11

    #3 분기 실적 공유가 목록에 없으면 됩니다. 없는 번호도 확인합니다.

    python -m booking cancel --id 99

    [취소 실패] 없는 예약 번호입니다

    python -m booking add --room R2 --title 마감회의 --date 2026-11-10 --start 17:00 --end 18:00 --booker 홍길동 --attendees 2

    [예약 완료] #6 2026-11-10 17:00~18:00 R2 마감회의

    python -m booking add --room R2 --title 늦은회의 --date 2026-11-12 --start 17:30 --end 18:30 --booker 홍길동 --attendees 2

    [예약 실패]
 - 운영 시간(09:00~18:00) 밖입니다.

    확인을 마치면 데이터 변경을 되돌립니다.

    1. 왼쪽 소스 제어 아이콘을 클릭합니다.
    2. data/reservations.json 오른쪽 되돌리기 아이콘(Discard Changes)을 클릭하고 확인합니다.

    확인: 인수 조건의 성공과 실패가 모두 맞았고, 소스 제어에 data/reservations.json이 없습니다.

    결과가 인수 조건과 다르면

    테스트가 통과해도 직접 실행 결과가 다르면 다 된 것이 아닙니다. 터미널 결과를 채팅에 붙여 넣고 "인수 조건은 ○○인데 결과가 △△입니다. 고쳐 주세요"라고 요청합니다.

    STEP 5. 이슈 번호를 넣어 커밋하고 올리기¶

    1. 소스 제어에서 바뀐 파일이 코드와 테스트뿐인지 다시 봅니다.

    2. 메시지 칸에 이슈 번호를 넣어 입력합니다. 내 스토리에 맞게 바꿉니다.

      겹치는 예약 막기와 테스트 추가 (#3)

    3. Commit을 클릭합니다. 스테이징을 묻는 창이 뜨면 Yes를 누릅니다.

    4. Publish Branch를 클릭합니다.

    확인: github.com 팀 리포지토리에서 브랜치 목록(main 버튼 → View all branches)에 story-<내번호>가 보입니다.

    커밋 메시지의 #번호

    커밋 메시지에 #3을 넣으면 GitHub가 그 커밋을 이슈 #3에 연결해 보여 줍니다. 이슈를 열면 "이 이슈를 언급한 커밋"이 기록으로 남습니다.

    PR은 6교시에 엽니다

    6-1에서 모두 함께 PR을 열고, Copilot 코드 리뷰와 BA 리뷰를 받습니다. 일찍 끝났으면 기다리는 동안 다른 팀원의 STEP 4를 함께 확인해 줍니다.

    다 됐는지 확인¶

    • story-<내번호> 브랜치에서 작업했다
    • /plan으로 계획을 받고 인수 조건이 테스트에 들어갔는지 확인했다
    • python -m pytest가 모두 통과한다
    • 내 스토리 탭의 명령으로 성공과 실패를 직접 확인했다
    • data/reservations.json 변경을 되돌렸다
    • 커밋 메시지에 #내번호가 있고, 브랜치를 Publish했다

    막히면¶

    S3: cancel이라는 명령이 없다고 나와요

    booking/__main__.py에 cancel 하위 명령이 추가되지 않은 것입니다. 채팅에 "python -m booking cancel --id 3을 실행하면 invalid choice가 나옵니다. main.py에 cancel 명령을 추가해 주세요"라고 요청합니다.

    S4: 17:00~18:00이 여전히 운영 시간 밖이라고 나와요

    rules.py의 운영 시간 비교가 그대로인 것입니다. 2교시에 고친 곳과 같습니다. 그 줄을 선택하고 "18:00에 끝나는 예약은 허용해야 합니다"라고 요청합니다.

    S2: 정원 4명에 4명도 실패해요

    >=로 비교한 것입니다. "정원과 같은 인원은 허용, 넘을 때만 실패"라고 요청합니다.

    Copilot이 다른 사람 스토리까지 구현했어요

    예: S1을 맡았는데 정원 검사도 넣었습니다. 6교시 병합 때 충돌이 커집니다. 소스 제어에서 해당 부분을 되돌리거나, 요청 위 Restore Checkpoint로 되돌린 뒤 "이슈 #3만 구현하세요"라고 다시 요청합니다.

    다른 팀원 브랜치에서 작업하고 있었어요

    상태 표시줄 브랜치 이름을 봅니다. 아직 커밋 전이면 브랜치 이름을 눌러 Create new branch...로 내 브랜치를 만들면 변경이 그대로 따라옵니다.
