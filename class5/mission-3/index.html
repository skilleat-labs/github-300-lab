    미션 5-3. 클라우드 에이전트에 이슈 맡기기¶

    이 미션에서 할 일

    • PM이 github.com의 Copilot에게 "테스트와 사용 설명을 추가해 달라"는 이슈를 쓰게 하고, 그 이슈를 Copilot(클라우드 에이전트)에게 맡깁니다.
    • 클라우드 에이전트가 GitHub에서 일하는 동안 팀은 6교시로 넘어갑니다.
    • 7교시 실습 7-3에서 돌아와 PR을 검토합니다.

    소요 시간 이슈 맡기기 약 3분 (에이전트 작업 시간 별도) 실습 장소 팀 리포지토리 room-booking-team<번호> (github.com) 관련 교안 클라우드 에이전트

    준비¶

    팀당 1건만 맡깁니다

    클라우드 에이전트는 AI Credits와 GitHub Actions 사용 시간을 씁니다. 팀당 이슈 1건만 맡깁니다. 팀원이 각자 맡기지 않습니다.

    • PM 한 명이 이슈를 쓰고, 나머지는 미션 5-2의 push를 마칩니다. 3인 팀은 PM을 겸하는 BA가 맡깁니다.

    클라우드 에이전트와 VS Code의 Agent는 무엇이 다른가요?

    VS Code의 Agent는 내 PC에서 내가 지켜보며 승인하고 일합니다. 클라우드 에이전트는 GitHub 쪽에서 혼자 일하고, 끝나면 항상 PR을 엽니다. 내 PC를 꺼도 일이 진행됩니다.

    STEP 1. (PM) Copilot에게 이슈를 쓰게 하고 그대로 맡기기¶

    5-1처럼 github.com의 Copilot에게 이슈 초안을 맡기고, 같은 요청에서 이 이슈를 Copilot에게 맡겨 달라고 덧붙입니다. 이슈가 만들어지면 클라우드 에이전트가 바로 일을 시작합니다.

    1. 새 탭에서 github.com/copilot을 엽니다.

    2. 아래를 붙여 넣고 <PO아이디>, <번호>를 바꾼 뒤 Enter를 누릅니다.

      In <PO아이디>/room-booking-team<번호>, 아래 내용으로 이슈를 하나 만들어 주세요. 제목은 "report.py 테스트와 사용 설명 추가 (코드 동작은 그대로)"입니다. Assign this issue to Copilot.

## 배경
booking/report.py의 이용률 보고서는 테스트와 사용 설명이 없어 담당자가 바뀌면 이해하기 어렵습니다.

## 할 일
- tests/test_report.py에 usage_report() 테스트를 추가해 주세요. 건수, 시간, 이용률(없음, 낮음, 보통, 높음)과 경계값(정확히 2시간, 정확히 6시간)을 확인해 주세요.
- README.md에 python -m booking report 사용법과 이용률 기준 표를 추가해 주세요.

## 지켜야 할 것
- booking/ 폴더의 코드는 바꾸지 않습니다.
- 기준은 코드에 있는 그대로 씁니다. 코드에 없는 기준을 만들지 않습니다.
- 기존 테스트는 모두 통과해야 합니다.

    3. 초안에서 본문이 위와 같은지, Assignees에 Copilot이 있는지 확인하고 Create를 누릅니다. Copilot이 담당자에 없으면 초안의 담당자 칸에서 Copilot을 고릅니다.

    확인: 이슈의 Assignees에 Copilot이 보입니다.

    Copilot 초안 기능이 안 보이면: 직접 만들기
    1. github.com 팀 리포지토리 → Issues → New issue를 클릭합니다.
    2. 제목 report.py 테스트와 사용 설명 추가 (코드 동작은 그대로)와 위 본문(배경, 할 일, 지켜야 할 것)을 입력합니다.
    3. 오른쪽 Assignees 톱니 → 목록에서 Copilot을 고르고 Create(화면에 따라 Submit new issue)를 클릭합니다.

    화면이 조금 다를 수 있어요

    이슈의 Assignees에서 Copilot을 지정하는 방법은 공식 문서 검색 요약으로 확인한 것입니다. 목록에 Copilot이 없으면 아래 "막히면"의 첫 항목을 봅니다. 리포지토리의 Agents 탭도 github.com에서 Copilot을 쓰는 입구입니다.

    이슈를 잘 쓰는 것이 프롬프트입니다

    클라우드 에이전트는 이슈 본문을 보고 일합니다. 3교시에 배운 구조(배경, 할 일, 지켜야 할 것)가 그대로 이슈 본문이 됩니다.

    STEP 2. 맡겨 두고 넘어가기¶

    클라우드 에이전트는 작업에 시간이 걸립니다. 기다리지 않고 6교시로 넘어갑니다.

    확인: PM이 팀에 "맡겼습니다"라고 알렸습니다. 쉬는 시간에 Pull requests 탭을 한 번 봅니다.

    7교시에 돌아와서: PR 검토하기¶

    Copilot은 작업을 마치면 리뷰를 요청합니다. 아래 순서를 지킵니다.

    1. Files changed를 먼저 읽습니다. 바뀐 파일이 tests/test_report.py와 README.md 정도인지 봅니다. booking/이나 .github/workflows/를 바꿨으면 특히 주의합니다.
    2. 이상이 없으면 쓰기 권한이 있는 사람이 PR 병합 영역의 Approve and run workflows를 클릭합니다. 기본 설정에서는 Copilot이 올린 변경에 워크플로가 자동으로 돌지 않으니, 이 버튼 없이 기다려도 검사가 시작되지 않습니다.
    3. Checks에서 테스트 / test가 초록인지 봅니다.
    4. README의 기준을 코드와 비교합니다. booking/report.py는 > 6이면 높음, > 2이면 보통입니다. "넘으면"이 맞고, "이상"이라고 썼으면 틀린 설명입니다. 테스트도 정확히 2시간을 "낮음"으로 확인하는지 봅니다.
    검토 결과 결정
    테스트 통과, 설명이 코드와 같음 Draft이면 Ready for review를 클릭하고, BA가 Approve, PM이 병합. 3인 팀은 맡긴 사람이 BA라서 PO가 Approve, BA가 병합
    설명이나 기대값이 코드와 다름 병합하지 않음. PR 댓글에 @copilot을 붙여 고칠 점을 요청
    범위 밖 파일을 바꿈 병합하지 않음. 이유를 댓글로 남김

    사람이 해야 하는 일

    Copilot은 자기 PR을 Ready for review로 바꾸거나 승인, 병합할 수 없습니다. 그리고 Copilot에게 일을 맡긴 사람(PM)은 그 PR을 승인할 수 없습니다. 그래서 BA나 PO가 승인합니다.

    시간 안에 안 끝나면

    PR 상태만 확인하고 넘어갑니다. 검토와 병합은 수업 뒤에 해도 됩니다.

    다 됐는지 확인¶

    • (PM) 이슈를 쓰고 Assignees에 Copilot을 지정했다 (팀당 1건)
    • (7교시) 변경을 먼저 읽고 Approve and run workflows를 눌렀다
    • (7교시) README의 기준이 코드와 같은지 확인했다
    • (7교시) 병합 여부를 팀이 결정했다

    막히면¶

    먼저 Copilot과 함께 해결합니다

    오류 메시지나 막힌 상황을 Chat(Ask)에 붙여 넣고 원인과 해결 순서를 묻습니다. 아래는 자주 막히는 경우입니다. 묻는 방법은 막혔을 때에 있습니다.

    Assignees 목록에 Copilot이 없어요

    이슈를 만든 사람의 Copilot 플랜을 봅니다. 클라우드 에이전트는 Pro에 포함되지만 Free에는 없습니다. 리포지토리 소유자(PO)가 Pro인지 확인하고, PO가 지정해 봅니다.

    한참 기다려도 PR이 안 열려요

    클라우드 에이전트는 시간이 걸릴 수 있습니다. 수업이 끝날 때까지 안 열리면 나중에 확인합니다.

    PR이 열렸는데 테스트가 돌지 않아요

    정상입니다. 변경 내용을 읽은 뒤 PR 병합 영역의 Approve and run workflows를 누릅니다.

    병합 버튼이 안 눌려요

    Draft 상태입니다. Ready for review를 먼저 누릅니다. 승인은 일을 맡긴 사람이 아닌 팀원이 합니다.

    테스트가 실패한 PR이 열렸어요

    병합하지 않습니다. Details 로그의 실패 줄을 PR 댓글에 남깁니다. 이것도 검토의 결과입니다.
